<objective>
Make the pipeline modules fit for a clean, recorded scheduled run:
1. Surface a forecast failure and a missing anomaly model in the run output (OD-3: `city_pipeline`
   catches forecast failures, so a missing ML model otherwise degrades silently).
2. Stop the three wasted NSRDB calls per live run (STATE.md item 3).
3. Move the stray stdout output to logging (STATE.md item 4) while keeping backfill's gate counting.
4. Load `.env` for local CLI runs of the orchestrator (STATE.md item 2).

Purpose: the runner (05-01) classifies each city from the orchestrator's `--output`; it can only
fail a run on a missing model if the output says so. The provider-error and log changes keep each
hourly run's record free of noise that would hide real failures.
Output: edits to five production modules and four test files, one new test file.

Phase 1 tests pin some of the shapes touched here (city_pipeline_test.py's pipeline key set,
dlr_orchestrator_test.py's summarize key list, backfill_archive_test.py's printed-gate counting).
This plan extends those pins; it never deletes a Phase 1 assertion.
