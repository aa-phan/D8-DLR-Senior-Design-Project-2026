<objective>
Add VAL-02 to the analysis: how well the live forecast band (method ml, OD-3) covers the ratings it
predicts, and how often and why the anomaly detector trips, measured from the same trace 03-01
writes. Add an offline replay that runs the real pipeline again on the same observations with the
naive forecast, so the report can show naive alongside ml as a reference.

Purpose: ROADMAP criterion 2 asks for forecast-band empirical coverage and detector flag rate per
city. The band is the detector's primary signal (G6), so its calibration decides how often a good
reading falls back to the static rating. `docs/data-science/PROJECT-STATUS.md` records that the
per-city ml forecast models did not beat naive on held-out MAE, and OD-3 chose ml anyway; the
naive reference lets the owner see what that choice costs on real data without this phase
changing it. The replay goes through the real pipeline (Phase 2 cleaning, G1-G6, archive) rather
than re-implementing the forecast-and-detector logic, so the comparison changes one thing only:
the forecast method.

Output: VAL-02 functions and the `replay` subcommand in `backend/real_data_validation.py`; offline
tests in `backend/tests/real_data_validation_val02_test.py`.
</objective>
