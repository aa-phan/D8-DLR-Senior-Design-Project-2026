<objective>
Prove the entire Phase 4 stack on one thin path: a single anomalous corridor reading is archived,
read back, turned into a 1-hour-ahead forecast with an empirical residual band, judged anomalous
against that band, and resolved by `DLRSafetyMonitor` to the static rating through the one fallback
helper Phase 3 already shipped.

Purpose: ROADMAP Phase 4 Success Criteria 1, 3 and 4. Every later plan in this phase expands
outward from this slice, so the architecture — archive row shape, forecast return contract, detector
`(bool, reason)` contract, and the additive G6 injection point — is settled and committed before any
horizontal build-out begins. The archive row shape in particular is one-way (D-07): once the forecast
and detector modules read it, changing it means migrating or discarding accumulated history, so it is
gated behind an explicit decision checkpoint here rather than discovered in Wave 2.

Output: three new backend modules (`historical_archive.py`, `ampacity_forecast.py`,
`anomaly_detector.py`), a sixth safety gate wired additively into `DLRSafetyMonitor`, every Phase 4
tunable centralized in `config.py`, and an end-to-end test that fails if any link in the chain breaks.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive file → forecast/detector | The append-only CSV is re-read on a later run. Anything that reached disk is treated as ground truth by every downstream model, so the write is the boundary that must be validated. |
| injected detector → `DLRSafetyMonitor.run_check` | A third-party-shaped object supplied at construction time executes inside the safety-critical gate chain. Its exceptions and its return values are both untrusted. |
| filesystem → pipeline | Disk state (missing directory, full disk, permissions, a partially written row) crosses into a code path whose job is to always produce a rating. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `historical_archive.append_observation` | high | mitigate | Every row passes `units_def.validate_pipeline_row(row, strict=False)` before any write; a row with violations is logged and rejected, not persisted. Archive columns deliberately reuse `PIPELINE_SCHEMA` spellings so no parallel schema object exists to drift. Task 3 proves it with an `air_temp=999.0` row that must not create the file. |
| T-04-02 | Tampering / Denial of Service | `DLRSafetyMonitor.run_check` G6 branch | high | mitigate | The detector call is wrapped in `try`/`except Exception`; the except branch returns `_fallback(result, "G6", ...)` at `self.static_rating`. A broken learned signal can only ever lower the reported rating, never let a reading through unexamined. Verified by `grep -c '_fallback(result, "G6"'` returning 2 and by the raising-stub test. |
| T-04-03 | Denial of Service | `historical_archive.append_observation` called from the rating path | medium | mitigate | The whole function body is exception-wrapped and returns a bool; `os.makedirs(..., exist_ok=True)` handles the missing directory. A disk problem degrades to "not archived this cycle". Proven by the unwritable-path test. |
| T-04-04 | Denial of Service | append-only CSV at `config.HISTORICAL_ARCHIVE_PATH` | low | accept | D-09 explicitly chose unbounded retention this phase; RESEARCH puts near-term volume at hundreds-to-low-thousands of rows per month, well inside what a flat CSV handles. Revisit trigger recorded here: a Parquet/SQLite migration and a retention window when monthly volume or read latency becomes noticeable. |
| T-04-05 | Information Disclosure | exception logging in `append_observation` | medium | mitigate | Log `str(exc)` only, never the exception's repr, matching the T-03-02 precedent in `corridor_discretization.resolve_point_observation` where a repr could echo request state carrying a provider token. |
| T-04-06 | Spoofing / Tampering | forecast value reaching a reported rating | high | mitigate | `DLRSafetyMonitor.py` never imports, names, or receives a predicted number — the detector hands it only a two-tuple of a boolean and a reason string.
