<objective>
Close DS-F5: make the two audit-flagged files ask `backend/config.py` which static rating applies to
the location being analysed, instead of unconditionally reading the 900 A fallback.

Purpose: `.planning/v1.0-MILESTONE-AUDIT.md` confirmed the gap with exact evidence — `backend/dlr_pipeline.py`
and `backend/ercot_dlr_merger.py` both hardcode `config.DEFAULT_STATIC_RATING` regardless of station or
city, while `config.STATIC_RATINGS` has held correct per-city values since Phase 3 and
`backend/corridor_discretization.py` has been consuming them correctly the whole time. The lookup table
exists; nothing selects from it on these two code paths. DS-F5 is the last requirement still open on the
v1.0 milestone.

Output: a `city: str = None` parameter on `run_pipeline`, `plot_dlr_summary` and `process_dlr_to_hourly`,
resolved internally through `config.STATIC_RATINGS.get(city, config.DEFAULT_STATIC_RATING)`; both files'
`__main__` demo blocks wired to `city="AUSTIN"`; two test files proving the resolved rating actually
changes the reported numbers; and a README parameter table that matches the new signatures.

**Reversibility (D-01, rated `costly` at discuss-phase):** removing `static_rating` changes the public
signature of `run_pipeline` and `plot_dlr_summary`. A repo-wide grep this session found no caller of
either function outside `backend/dlr_pipeline.py` itself and one README documentation row, so the blast
radius today is fully contained by this plan — but any future external caller passing `static_rating=`
breaks at the call site rather than degrading silently. Recorded, not gated: the developer already chose
this option at discuss-phase, so no checkpoint re-asks it.
</objective>
