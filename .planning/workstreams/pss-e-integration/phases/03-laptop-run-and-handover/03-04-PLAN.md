<objective>
Add the laptop's own commands to the launcher core of plan 03-01 and the one script Task Scheduler runs: an entry script that alone imports `psspy`, a `selftest` that isolates interpreter, folder and licence problems from study problems, a `probe` that runs Phase 2's drift guard on a case, a `hold-lock` that lets the laptop prove an overlapping start exits 4, and the dispatch of `gaps` and `credcheck` to the modules of plans 03-02 and 03-03.

Purpose: runbook steps 2 to 4 and 6 need one command each to get from "something does not start" to a precise answer. The laptop session (plan 03-07) cannot afford a ten-minute detour because the interpreter, the PSSPY folder, the licence or a signature is wrong and the only symptom is a stack trace. Each mode here is proved on the Mac against a stub or fake `psspy` and, for the entry script, in real `-I` subprocesses, so the laptop only has to show what the Mac cannot.
Output: `backend/psse_run_hourly.py`, additions to `backend/psse_job/launcher.py`, `backend/tests/psse_fake_launch.py`, `backend/tests/psse_laptop_modes_test.py`, `backend/tests/psse_entry_test.py`.

Honest scope: a stub `psspy.py` proves that the entry script finds a module in the configured folder, that `psseinit` and the output calls are made as designed, and that a missing function or a failed start gives the right row and exit code. It does not prove that real PSS/E has those functions with those parameter names, that `report_output(2, file, [0, 0])` redirects anything, or that `os.add_dll_directory` is needed or enough; the research took them from forum posts and a vendor blog. Every such statement in code comments carries UNVERIFIED and runbook step 2.

Questions carried forward: (1) Which PSS/E version, Python and licence does the laptop have (the guide's question 1)? `selftest` is how the answer is read off. (2) Is a `psseinit` bus count of 20000 (`PSSE_MAX_BUSES`) acceptable to the licence and large enough for the real case (the guide's questions 1 and 9)? Plan 03-07 reads it off the laptop.

## Design decisions (planner-locked; the research's Pattern 5 and selftest except where a reason is given)

| ID | Decision |
|----|----------|
| D-01 | The loader contract of plan 03-01 is `psspy_loader(cfg) -> a started psspy module`. The entry script's `load_psspy` appends PSSE_PSSPY_DIR (and the bin and site folders, through the launcher's `add_search_dirs`), imports psspy, then calls `launcher.start_psspy`, which calls `psseinit` with PSSE_MAX_BUSES and redirects the four output channels to `psse_output.log` inside PSSE_LOG_DIR. The start notes (one short, path-free sentence per output function: redirected, missing or failed with the exception class) are kept in the module-level list `launcher.LAST_START_NOTES`, replaced on each call, so selftest can print them although the loader returns only the module. |
| D-02 | LAUNCH_SURFACE has five rows (psseinit with parameter buses; report_output, progress_output, alert_output and prompt_output with parameters islct, filarg and options), each marked UNVERIFIED (research A2, A3: community and vendor sources). The output call is `(2, log file path, [0, 0])`; a failed or missing output function is a note, never fatal, because a console banner is a nuisance and not a failed run. `psseinit` failing is fatal: PsseUnavailable. |
| D-03 | `check_launch_signatures(psspy_module)` returns `probe.ProbeRow` rows named `launch:NAME` with the same PASS, FAIL and SKIP rules as `probe.check_signatures` (missing function FAIL, uninspectable signature SKIP, missing parameter name FAIL, a keyword-catching signature with missing names SKIP). It is written here because probe.py is frozen; it duplicates about thirty lines on purpose. |
| D-04 | `selftest` takes the lock, calls the loader, prints the Python version and bitness (`sys.version` first token and `sys.maxsize > 2**32`, no struct import), "PSS/E started", the PSS/E version (`psse_api.PsseApi(module).version()`; "unknown" or an adapter failure is a FAIL row), the start notes, the launch rows and a count line (the format of `probe.format_report`), and exits 0 when no FAIL and the start worked, else 6. A loader failure prints "PSS/E could not be started: ClassName: text" with absolute paths scrubbed and exits 6. |
| D-05 | `probe` takes the lock, calls the loader, loads the mapping when PSSE_MAPPING_PATH is set (`mapping.load_mapping(path, allow_placeholder=flag)`; a MappingError prints one line "mapping file not usable" and, only with --show-identifiers, its text, and exits 6), runs `probe.run_probe(module, case_path, mapping, write_check, show_identifiers)`, prints `probe.format_report(rows)` and exits 0 when `probe.probe_ok(rows)` else 6. `--write-check` prints a notice first: the loaded case changes in memory only and is reloaded from disk, the file is never saved, and the runbook says to use a copy of the case. `--show-identifiers` prints a notice that the output must not be pasted into the repository. |
| D-06 | `hold-lock --seconds N` (default 60, accepted 1 to 600) takes the lock, prints `locked` (flushed), sleeps in one second steps, releases and exits 0; a lock that cannot be taken is exit 4. It exists so the laptop can show, with the real Task Scheduler, that a start made while another process holds the lock ends with exit 4 and no record (runbook step 6), and so a test can prove the same across two real processes. |
| D-07 | `gaps` and `credcheck` do not take the lock and do not start PSS/E. The launcher calls `gaps.run(cfg, since, until, fail_on_gaps, out)` and `credcheck.run(cfg, skip_rest, write_proof, out)` (the contracts of plans 03-02 and 03-03) through a `modes` argument of `main`: a dict of mode name to a zero-argument callable returning the module, default loading `psse_job.gaps` and `psse_job.credcheck` inside the call. `--since` and `--until` are parsed by `ratings.parse_ts` (an offset is required) at argument-parsing time, so a bad value is a usage error, exit 2. |
| D-08 | Required keys per mode come from `launcher.CONFIG_KEYS` (plan 03-01): selftest needs PSSE_PSSPY_DIR; probe needs PSSE_CASE_PATH and PSSE_PSSPY_DIR; gaps needs SUPABASE_PSSE_DB_URL; credcheck needs SUPABASE_PSSE_DB_URL and, unless --skip-rest, SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY (the data uses the pseudo-mode name `credcheck-rest` for the second group); hold-lock needs nothing. A missing key is exit 2 naming the keys. |
