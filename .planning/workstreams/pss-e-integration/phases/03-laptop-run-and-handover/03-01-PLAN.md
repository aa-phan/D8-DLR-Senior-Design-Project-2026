## Design decisions (planner-locked; the research's recommendations except where a reason is given)

| ID | Decision |
|----|----------|
| D-01 | The configuration file is the whole configuration: the process environment is never read for a setting (research suggested overlaying environment variables; a stray variable could silently point an unattended job at another database, so it is not done). `--config` is required, so no default path depends on an environment variable either. `read_config` returns one resolved dict: the defaults of PSSE_LOG_DIR (a `logs` folder next to the config file), PSSE_LOCK_PATH (`psse_job.lock` next to it), PSSE_MAX_BUSES (20000) and PSSE_PREFLIGHT (1) are filled in, so every consumer sees the same values. |
| D-02 | One command with subcommands. This plan builds `run` (with `--config`, `--dry-run`, `--allow-placeholder`); plan 03-04 adds selftest, probe, gaps, credcheck and hold-lock to the same parser and runner table. Task Scheduler runs `run`. The verb is required; argparse usage errors are exit 2. `main` dispatches through a module-level table of runner functions keyed by mode, so plan 03-04 adds entries without restructuring. |
| D-03 | Exit codes: 0 ok or fallback written or already recorded; 1 failed run recorded (dry-run: study or validation failed); 2 usage or configuration; 3 no record could be written (job.py's code: the SCH-02 gap); 4 another instance holds the lock; 5 gaps found with --fail-on-gaps (plan 03-04's gaps mode); 6 a check mode (selftest, probe, credcheck, gaps) could not complete or found a failure (plan 03-04); 7 unexpected launcher error. 0, 1 and 3 are job.py's constants unchanged. `EXIT_CODES` lists all eight now so the guide's table and the other modules' constants have one source. |
| D-04 | The lock is a non-blocking OS file lock held from before PSS/E starts until after run_once returns (one PSS/E process per run: psspy state is process-global and a licence seat is only released by process exit). A second instance exits 4 and records nothing, because it never started a study. Every mode that starts PSS/E takes it (run and dry-run here; selftest, probe and hold-lock in plan 03-04); gaps and credcheck do not. |
| D-05 | Before PSS/E starts, `run` opens a TCP connection to the database host and port with a 5 second timeout (host and port from SUPABASE_PSSE_DB_URL, port default 5432; switch PSSE_PREFLIGHT=0). Failure is exit 3 and no PSS/E licence is checked out. Dry-run does no preflight. |
| D-06 | If the loader raises (PsseUnavailable or anything else), the launcher still records the run: `study.failing_study("load_case", "PSS/E could not be started: ...")` with the case label and the case file's sha256 and mapping_sha256 None. The message names the exception class and a path-scrubbed text, never a path. |
| D-07 | Dry-run mirrors run_once step for step up to the connect (select_ratings, the study, validate_results, build_run_record, result_rows) and never connects. A differential test proves its counts equal a real run's. |
| D-08 | A non-loopback database host needs sslmode require, verify-ca or verify-full in the URL (libpq's default prefer falls back to plaintext); loopback hosts are exempt so local tests need no TLS. |
| D-09 | `--allow-placeholder` is accepted only together with `--dry-run`. A real run therefore always refuses a mapping marked placeholder (Phase 2), and no configuration key can switch that off. |
| D-10 | `PSSE_SITE_DIR`, `PSSE_PSSPY_DIR` and `PSSE_BIN_DIR` are appended to sys.path (never inserted first), so a module planted in a user-writable folder cannot shadow the standard library. |
| D-11 | Case path and mapping path are not checked for existence by the configuration reader: a missing case or mapping must become a recorded failed run (stages load_case and mapping), not a silent exit 2 each hour. They must be absolute paths, because Task Scheduler's working directory is not the repository's. |
