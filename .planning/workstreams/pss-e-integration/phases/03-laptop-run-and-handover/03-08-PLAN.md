What no earlier plan can show is the live database with the real role, the real case with the real mapping, and the job running unattended for a day. This plan is those steps, each behind the precondition that its input exists. `psse_run` and the result tables are append-only and the writer role has no DELETE, so every write is permanent. There are therefore two separate permanent-write decisions, never one: decision 1 (task 3) authorises one proof write; decision 2 (task 5) authorises the scheduled task, which writes every hour it runs.

Requirement coverage by this plan: DBX-02 closes (task 1). TST-02 closes (tasks 2 to 4). SCH-02 closes and SCH-01 is confirmed on the real task (task 6, behind decision 2). DOC-01 closes (task 7, with the evidence of plan 03-07). REQUIREMENTS.md statuses stay Pending until the orchestrator marks them after each step passes; this plan's SUMMARY states which criteria are met.

Order: tasks 1 and 2 do not depend on each other. Task 1 needs only Phase 6 live; task 2 needs only the real inputs. Either may run first, and the plan may pause between them. Task 3 (decision 1) needs both to have passed; task 4 needs a write-one answer; task 5 (decision 2) needs task 4 to have passed; task 6 needs an enable answer; task 7 needs whatever has been done and says plainly what has not.

Honest scope: the proof run and the scheduled runs use static ratings, because every `city_rating` row is provisional until production-pipeline Phase 7's go; their results must not be presented as a full N-1 study (the screen covers line outages near the mapped branches only) or as a dispatch the grid operator should rely on until Power Systems has reviewed the definitions and answered the eight questions of `docs/data-science/decisions/psse_study_definitions.md`. A real run replaces the case's own ratings on the mapped lines in memory only (the case file is never saved), so no customer file changes. No retention rule exists for the result tables in this milestone (the spec lists it as an open question), so the number of permanent row sets a decision creates is part of the decision.

Questions this plan answers or leaves open (carried to the record): the guide's questions 3, 4, 5 (which now includes decision 2's acceptance of hourly permanent rows), 8, 9 and 10, and 7 if not yet answered. Both decisions are the user's.
