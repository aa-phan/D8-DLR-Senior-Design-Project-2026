<objective>
Give the adapter its whole-case scaling call: read the case's total load and generation, and set them to new totals with one `scal_2` call, with the argument layout kept in one table that the laptop check of plan 04-06 confirms or corrects. Teach the fake psspy the same call so the study can be built against it.

Purpose: CD-2 says the job applies each city's targets with its own scaling call and never runs the recorded `.idv` scripts. `psse_api.py` is the only module that names psspy functions, so the call and its read-back live here. Only the increment form of `scal_2` is proven on the laptop (U11); the new-total layout comes from community forum posts (research A1, A4, A10), so it is isolated in `SCALE_LAYOUT`.
Output: `ScaleLayout`, `SCALE_LAYOUT`, `CaseTotals`, `PsseApi.read_totals`, `PsseApi.scale_case`; generation and the whole-case `scal_2` modes in the fake; tests.

Honest scope: the fake is built from the same layout the adapter sends, so these tests prove argument handling, validation and error mapping, not that PSS/E 36.4 reads the slots this way. The laptop check (plan 04-06) and the probe row (plan 04-05) prove that.
</objective>
