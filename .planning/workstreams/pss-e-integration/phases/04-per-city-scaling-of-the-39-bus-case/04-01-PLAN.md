## Design decisions (planner-locked)

| ID | Decision |
|----|----------|
| PD-1 | `Scaling = collections.namedtuple("Scaling", ["load_mw", "gen_mw", "basis"])`; `SCALING_BASES = ("average", "peak")`; `_SCALING_KEYS = ("load_mw", "gen_mw", "basis")`; `CityMapping` fields become `city, branches, sink_buses, transfer_max_mw, scaling` (the only positional construction is the return at the end of `_parse_city`; tests use `_replace`) |
| PD-2 | Messages, all following the existing problem-list style and never echoing a submitted value: `cities.<CITY>.scaling: missing`, `cities.<CITY>.scaling: must be an object`, `cities.<CITY>.scaling.<key>: missing`, `cities.<CITY>.scaling.<key>: unknown key` (key cut by `_short`), `cities.<CITY>.scaling.<load_mw or gen_mw>: must be a finite number greater than 0`, `cities.<CITY>.scaling.basis: must be one of average, peak`. Version: `schema_version: must be the integer 2 (version 2 adds the per-city scaling block)` |
| PD-3 | No upper bound on the targets in the parser; the study compares each target with the case's own totals (plan 04-03). A value written as `1e999` parses to infinity and is refused by the finiteness check |
| PD-4 | The duplicate rule moves inside `_parse_city`: `seen` becomes a per-city dict created inside `_parse_city` (the shared `seen` argument and the cross-city message go away); within one city a repeat in either orientation is refused with `cities.<CITY>.branches[<i>]: branch <key> is listed twice in this city`, the same text style as the existing sink-bus duplicate |
