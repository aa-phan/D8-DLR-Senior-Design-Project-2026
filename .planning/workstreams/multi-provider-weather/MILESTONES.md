# Milestones

## v1.1 Multi-Provider Weather (Shipped: 2026-09-15)

**Phases completed:** 5 phases, 15 plans, 37 tasks

**Key accomplishments:**

- PIPELINE_SCHEMA v3 adds four categorical per-field provenance columns (wind_source, temp_source, humidity_source, solar_source), validated by allowed_values membership, and `weather_provider.attach_provenance` tags synoptic station fetches with their source end-to-end.
- `fetch_weather` now accepts either a station-ID list or a `(lat, lon)` grid tuple through one type-dispatched `location` parameter with an explicit shape guard, and the adapter gained an internal `resolve_station_city` helper (haversine to `config.CITY_COORDINATES`) that Plan 06-03's city-keyed merge will consume — with zero edits to any existing caller.
- A station-sourced frame and a grid-sourced frame now combine into exactly one row per (city, datetime_utc) via `merge_observations`'s `combine_first`, with per-field provenance travelling with its value, proven end-to-end through a synthetic grid provider against `PIPELINE_SCHEMA` v3.
- ASOS 1-minute wind/temp rows now transparently supplement every Synoptic station-path `fetch_weather` call, unit-converted via `units_def.Q`, provenance-tagged, and fail-loud on genuine failures while treating a real sensor outage as a non-event.
- Phase 6's grid path (`_fetch_grid`) gets its first real implementation: `fetch_weather((lat, lon), start, end, provider="open_meteo")` now returns all five weather variables from a single Archive API request, standardized to `PIPELINE_SCHEMA` units with tz-aware UTC timestamps and `open_meteo` provenance, closing WX-04.
- One merged frame carrying Synoptic, ASOS, and Open-Meteo rows proves ROADMAP Success Criteria 3 and 4 for WX-02 and WX-04 simultaneously; a source-level gate confirms neither new provider module reads a secret; and a human-confirmed live check against both real endpoints closes the phase's one mocked-test blind spot.
- Phase 6/7's grid path gets its second real implementation: `fetch_weather(config.CITY_COORDINATES[city], start, end, provider="nsrdb")` returns NSRDB PSM v4 GHI as `solar_radiation` with `nsrdb` provenance, a literal city key, and a longitude-first WKT request pinned against every silent-corruption failure mode the phase's own threat model flagged, closing the tracer half of WX-03.
- `fetch_nsrdb` now decomposes any `[start, end]` window — including one crossing a calendar-year boundary — into per-year requests, reassembles them into one ordered/de-duplicated frame, and raises a credential-redacted `ValueError` for either of NSRDB's two structurally different error-body shapes, closing the general-case half of WX-03.
- Behavioural credential-source gate confirms `nsrdb_provider` reads `NREL_API_KEY`/`NREL_API_EMAIL` only from the environment; Phase 8's documentation (C4 spec, README, ACKNOWLEDGEMENTS) is brought current; and a real NSRDB pull for Austin closes both research assumptions (`GHI Units == "w/m2"`, a credential-free `ValueError` for an out-of-range year) that no mocked test could reach — closing WX-03 and Phase 8.
- `provider="tceq"` scrapes TCEQ's `daily_summary.pl` HTML report via BeautifulSoup and returns a real, unit-converted, fixed-offset, range-checked, provenance-tagged Corpus Christi CAMS 83 weather frame through the actual `fetch_weather` dispatch.
- `fetch_tceq` now serves any window up to 31 days over any of the four CAMS cities via real per-local-calendar-day decomposition, with Austin/Midland's absent humidity nulling cleanly and every unreachable/malformed/missing-field condition raising a specific, named error instead of returning data.
- TCEQ's no-credential source gate is load-bearing-proven, the C4 spec and ACKNOWLEDGEMENTS.md now describe the shipped five-provider integration, and a live fetch of all four CAMS sites (after fixing two report-parsing bugs the live check itself discovered) returned real, plausible, correctly-provenanced weather data — with the plan's blocking-human checkpoint awaiting confirmation of that evidence.
- `weather_provider.fetch_weather` now auto-retries a failing or empty TCEQ station-path request via Synoptic (fallback=True default), with honest provenance, a WARNING audit log, and zero leakage into any of the 18+ pre-existing fail-loud error classes.
- Generalized Plan 10-01's one-path TCEQ-to-Synoptic tracer to the full WX-06 surface: an `_as_grid_shaped` seam wires the NSRDB grid path into the same fallback, all eight city/primary combinations are individually proven to resolve the correct station, both-providers-exhausted always raises instead of returning an empty frame, and a fallback-sourced row is proven to validate/merge/attribute exactly like any other pipeline row.
- `PRD.md` §7.1 and `data_provider.md` now record the ratified per-variable weather-provider composition Phases 6-10 actually built (TCEQ+ASOS wind/temp, NSRDB solar, Open-Meteo historical backfill, Synoptic automatic fallback), `C4-weather-ingestion.md` documents Phase 10's fallback wiring, and the fallback has now been confirmed against the live Synoptic and NSRDB endpoints — all four `SYNOPTIC_FALLBACK_STATIONS` return real data, and both the station-path and grid-path fallbacks were exercised end-to-end against genuine provider failures with correct provenance.
