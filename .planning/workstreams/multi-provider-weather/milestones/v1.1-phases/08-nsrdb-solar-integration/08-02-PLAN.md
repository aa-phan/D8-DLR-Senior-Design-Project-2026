<objective>
Expand the proven single-year slice into the real contract: any window, including one that crosses a
calendar-year boundary, and every way the request can be rejected.

Purpose: Plan 08-01 proved the path end to end for the common case. Two things remain that no other
provider in this codebase has ever needed. NSRDB's CSV endpoint is year-scoped rather than
range-scoped, so a `[start, end]` window has to be decomposed into per-year requests and reassembled
— the single most consequential finding of the phase's research, and a defect that would be invisible
in the returned frame. And NSRDB returns two structurally different error bodies depending on whether
the key was accepted, one of which echoes the API key back.

Output: the year-chunking loop and window reconstruction; a local lower-bound coverage guard; the
dual-shape error handler with credential redaction; the GHI-units metadata check; and the
cross-provider provenance assertions that prove D-02 holds through the merge.
</objective>

## Assumptions carried forward from research, and how each is handled

08-RESEARCH.md leaves two items genuinely unresolvable without a real API key. Neither is silently
resolved here; each is handled so the code is correct under either outcome, and the live confirmation
is Plan 08-03's checkpoint.

| # | Research item | Handling in this plan |
|---|---------------|-----------------------|
| A2 | GHI response units assumed W/m², never read from a real response | `_parse_psm4_csv` compares the response's `GHI Units` metadata field against `NSRDB_ACCEPTED_GHI_UNITS` after normalizing case, spacing and the two common superscript spellings — and skips the check entirely when the field is absent, matching `open_meteo_provider`'s "skip keys the response omits" convention. A grossly wrong unit is also caught independently by `_range_check`. The exact literal spelling is recorded by Plan 08-03's live check, after which the accepted set can be narrowed. |
| A3 / OQ1 | Exact out-of-range-year error text could not be isolated | The error handler matches on a non-2xx status plus the generic errors-array shape, never on a wording. It raises on any structured error NSRDB returns. No test asserts a specific NREL sentence. |

One additional behaviour is specified here rather than left to the executor, because the two
reasonable readings differ by 23 rows: an `end` argument written as a bare calendar date covers that
whole day. Phase 7 confirmed live that Open-Meteo's single-day window returns 24 rows; a caller
writing the same window against this provider should not silently get one. The rule is mechanical —
an `end` string containing neither a `T` nor a `:` is a bare date — so it is testable rather than
heuristic.
</planner_assumptions>

**`backend/nsrdb_provider.py`** — replace Plan 08-01's single-year computation with the general
window decomposition. Nothing about the request parameters, the parse, or the range check changes.

Add `NSRDB_FIRST_COVERED_YEAR: int = 2018` as a module constant, with a comment stating that PSM v4
GOES CONUS coverage begins in 2018, that this bound is a fixed product fact which cannot move
backwards, and that there is deliberately no matching upper-bound constant because the product's most
recent covered year advances as NREL publishes and a local ceiling would reject a year that exists.

Add `_window_bounds(start: str, end: str) -> tuple[pd.Timestamp, pd.Timestamp]`. Coerce each argument
with `pd.Timestamp`, localizing to UTC when tz-naive and converting when tz-aware, exactly as
`open_meteo_provider._to_archive_date` does, raising `ValueError` naming the offending value when it
cannot be parsed. Then apply the bare-date rule to `end` only: when the raw `end` string contains
neither a `T` nor a `:`, it names a calendar day rather than an instant, so advance the resolved bound
to the last microsecond of that day. The docstring states why: Phase 7 confirmed live that Open-Meteo
returns a full day's rows for a single-day window, and a caller writing the same window against this
provider should get the same 24 rows rather than the single midnight row a literal reading would
select. Finally raise `ValueError` when the resolved end precedes the resolved start, naming both.

Add `_years_spanned(start_ts, end_ts) -> list[int]` returning
`list(range(start_ts.year, end_ts.year + 1))`. Raise `ValueError` naming the offending year and
`NSRDB_FIRST_COVERED_YEAR` when any spanned year precedes the covered range. Do this before any
request is issued, so an out-of-range request costs nothing and fails with a message about the
product rather than with a remote validation error.

Rewrite `fetch_nsrdb`'s body: look up both credentials once, resolve the bounds with `_window_bounds`,
compute the year list, then loop. Inside the loop build the same parameter dict Plan 08-01 built, with
`names` set to that iteration's year, issue one `requests.get`, parse, and append the per-year frame
to a list. Credentials are looked up once outside the loop, not per iteration — an environment that
changes mid-loop is not a case worth modelling, and re-reading would make the number of `os.getenv`
calls a function of the window length.

After the loop, concatenate with `pd.concat(frames, ignore_index=True)`, filter to the resolved bounds
inclusive, sort by `datetime_utc`, drop any duplicate timestamp arising at a year seam keeping the
first occurrence, and reset the index. Then run `_range_check` on that final frame and return it.
Raise `ValueError` naming both bounds when the filtered frame is empty: on this path an empty result
means the provider returned nothing usable for what was asked, and Phase 7's D-05 precedent is to
raise rather than hand back a well-formed emptiness that a caller will mistake for night-time.

Record the request-volume consequence in `fetch_nsrdb`'s docstring: one request per spanned calendar
year per city, against a documented standard-key limit of 1,000 requests per hour, so a four-city
eight-year backfill is 32 requests. No retry, no backoff and no concurrency are added here — a
rate-limited response is a non-2xx and is handled by Task 2's error path like any other.

Leave `_parse_psm4_csv`, `_range_check`, `_wkt_point` and both credential helpers untouched in this
task.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NSRDB error body → exception message → log file / traceback | The JSON error body echoes the request `inputs`, which include `api_key`. The naive diagnostic gesture — quoting the body — is the one that leaks the credential. |
| Caller's `[start, end]` window → per-year requests → reassembled frame | The only provider in this codebase whose returned window is reconstructed rather than passed through. A reconstruction defect is invisible in the frame's shape. |
| Response `GHI Units` metadata → `solar_radiation` values | The single unverified assumption of the phase (A2). A unit error here reaches the IEEE 738 model as a plausible number. |
| NSRDB solar row → `merge_observations` → a pipeline row | Where D-02's "wind/temp/humidity stay null on NSRDB rows" either holds or quietly stops holding. |
