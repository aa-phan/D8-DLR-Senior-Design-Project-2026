## Discretion items resolved at plan time, with reasons

These are the items 08-CONTEXT.md left to Claude's Discretion plus the Open Question 08-RESEARCH.md
left unresolved. Each is settled here deliberately rather than inherited.

**1. Credential-absent exception type: `EnvironmentError`, not `ValueError`.**
08-CONTEXT.md's discretion note said "default to the `dlr_pipeline._token()` precedent", describing
that precedent as `ValueError`. 08-RESEARCH.md Pitfall 1 read the actual source: `_token()` raises
`EnvironmentError` (a built-in alias of `OSError`). This plan uses `EnvironmentError`, and not only
because it is the literal precedent — it is the type that carries information here. This module also
raises `ValueError` for malformed *response* data, matching `asos_provider`/`open_meteo_provider`.
Keeping "this machine is misconfigured" on a different exception branch from "this provider sent
something wrong" is what lets Phase 10's fallback wiring (WX-06) fall back on the second and refuse
to fall back on the first — silently falling back to Synoptic because someone forgot to export an
env var would hide a configuration error behind degraded data.

**2. The required `email` parameter: a second env var, `NREL_API_EMAIL`.**
NSRDB rejects any request without a syntactically valid `email` parameter (live-confirmed, 08-RESEARCH.md
Open Question 2). It is not a secret, so hardcoding it would not be a security defect — but it would
commit one person's address into a repository submitted for a course, and it would keep being sent
after that person's key is revoked. It is read with the same env-var-or-raise helper as the key, so
the two credential-adjacent values fail identically and are documented together in Plan 08-03.

**3. Env-var naming: `NREL_API_KEY` / `NREL_API_EMAIL`, not `NLR_*`.**
08-RESEARCH.md A1 flags the tension: the organization is now the National Laboratory of the Rockies,
but WX-03, the ROADMAP, `data_provider.md` and PROJECT.md all say "NREL developer API key". Matching
the requirement's own wording keeps the env var greppable against the documents that ask for it. The
rename is recorded in the module docstring and in Plan 08-03's C4 spec update, so a future reader
meets the discrepancy rather than trips over it.

**4. The four optional request-metadata parameters are sent, not omitted.**
08-RESEARCH.md A4 confirms only that omitting `full_name`, `affiliation`, `reason` and `mailing_list`
produces no *additional* validation error under the public demo key — it could not confirm a real key
succeeds without them, and `pvlib` always sends them. Sending fixed, non-secret project values costs
one dict literal and removes an unverified assumption from the one code path this phase cannot
exercise live until Plan 08-03.

**5. Historical-depth handling is split by whether the bound is stable.** PSM v4 GOES CONUS covers
2018 onwards. The lower bound is a fixed product fact and gets a local pre-flight guard in Plan
08-02. The upper bound moves forward every time NREL publishes a year, so it is left to the
endpoint's own structured 400 rather than hardcoded — a local upper-bound constant would become a
self-inflicted outage the first time the project asks for a year that exists.

**6. Reversibility review (REVERSIBILITY_GATES).** No task in this phase is one-way. The env-var
names, the exception type, the base URL and the attribute list are each a single-module edit plus a
test-fixture update. D-02 (solar-only field population) is rated *costly* in 08-CONTEXT.md — flagged
on Task 1 below, not gated — because reversing it means auditing downstream consumers for reliance
on the null, not migrating data or breaking a published contract. No `checkpoint:decision` is
inserted anywhere in Phase 8.

Laboratory of the Rockies rename left the previous `developer.nrel.gov` hostname non-resolving, while
the requirement and env-var wording deliberately keeps saying NREL to match WX-03.

`_nrel_api_key() -> str`: read `os.getenv("NREL_API_KEY", "")`; when empty, raise `EnvironmentError`
whose message names the variable and points at the signup page on the `developer.nlr.gov` host —
modelled literally on `dlr_pipeline._token()`, including that it names the variable and never echoes
the value. Return the value.

`_nrel_contact_email() -> str`: identical structure for `NREL_API_EMAIL`, with a message stating that
NSRDB requires a syntactically valid contact address on every request and that it is kept in the
environment rather than in source so a course submission carries no personal address. Do not validate
the address's syntax locally — the endpoint is the authority on that, and a local regular expression
would reject valid addresses the endpoint accepts.

`_wkt_point(lat: float, lon: float) -> str`: return `f"POINT({lon:.4f} {lat:.4f})"`. Its docstring
carries the whole warning: this function's parameter order is latitude-first to match
`config.CITY_COORDINATES` and `_fetch_grid`, while the string it produces is longitude-first because
that is what the WKT specification and this endpoint require; getting it backwards yields
syntactically valid WKT for a different point on Earth, so nothing downstream raises, the range check
passes, and the row is still tagged with the caller's city. Keep this swap in one named function
rather than inline in the parameter dict, so there is exactly one place in the codebase where the
order is decided and exactly one place a test has to pin.

`_parse_psm4_csv(text: str) -> tuple[pd.DataFrame, dict[str, str]]`: the response body carries two
metadata header lines before the real column-name row. Build the metadata dict by reading the first
two lines with the `csv` module or `pd.read_csv(StringIO(text), nrows=1)` and zipping field names to
values — not with a bare `str.split(",")`, because a metadata value such as a city name can itself
contain a quoted comma. Then build the data frame with `pd.read_csv(StringIO(text), skiprows=2)`.
Raise `ValueError` naming what was found when the body has fewer than three lines, or when the data
frame lacks any of the columns `Year`, `Month`, `Day`, `Hour`, `Minute`, `GHI` — an HTML error page or
a redirected response would otherwise reach `pd.read_csv` and look parseable, which is exactly the
failure mode `asos_provider`'s own first-line header guard exists to catch.

Build `datetime_utc` with `pd.to_datetime(frame[["Year", "Month", "Day", "Hour", "Minute"]], utc=True)`
— the `utc=True` is load-bearing for the same reason it is in `open_meteo_provider`: a tz-naive column
aligns against nothing in the rest of the pipeline and produces an all-null merge rather than an error.
Build `solar_radiation` with `pd.to_numeric(frame["GHI"], errors="coerce")`. Return
`frame[["datetime_utc", "solar_radiation"]]` together with the metadata dict, and return no other
column: D-02 is a statement about what an NSRDB row does not carry, and a column that is merely
dropped later is a column a future edit can re-add without noticing what it re-admits.

`_range_check(frame: pd.DataFrame) -> None`: mirror `open_meteo_provider._range_check` exactly, over
the single column `solar_radiation`, reading both bounds from
`units_def.PIPELINE_SCHEMA["solar_radiation"]["range"]` rather than writing them out. Raise
`ValueError` naming the column, the offending value and both bounds.

`fetch_nsrdb(lat: float, lon: float, start: str, end: str) -> pd.DataFrame`: for this task, handle a

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Environment (`NREL_API_KEY`, `NREL_API_EMAIL`) → outbound request params | A credential crosses from process environment into an HTTP query string and into any exception message or log line built from it. |
| NSRDB CSV response body → `PIPELINE_SCHEMA["solar_radiation"]` | A third-party body becomes the solar input to the IEEE 738 thermal model. A wrong unit or a wrong grid point reaches C5 as a plausible reading. |
| Caller coordinates → `_wkt_point` → NSRDB grid cell | The only place in this phase where a correct-looking transformation can silently address a different point on Earth. |
| Grid path ↔ station path dispatch | D-05 requires `provider="nsrdb"` be reachable only on the grid path; a dispatch leak would serve satellite-derived solar to a station-path caller as if it were a station observation. |
