    10-02: the fallback fires for a failing or empty TCEQ/NSRDB result; it does NOT fire for a
    caller-shaped error (unknown provider, wrong path, multiple CAMS IDs, unresolvable
    coordinates), for Open-Meteo, or for an `EnvironmentError` signalling a missing credential
    -- a misconfigured machine stays visible rather than being quietly served from the
    fallback. When Synoptic also fails, the adapter raises an error naming both providers
    rather than fabricating a row.
  </decision>

  <what-built>
    Synoptic is wired as the automatic fallback for a failing or empty TCEQ or NSRDB request,
    across all four cities and both adapter paths, with provenance recording `synoptic` and a
    WARNING log naming the failed primary.
  </what-built>

  <why-human>
    Every automated test in Plans 10-01 and 10-02 monkeypatches `dlr_pipeline.fetch_timeseries`,
    so not one of them proves the fallback can actually retrieve data. Three of the four
    station IDs in `config.SYNOPTIC_FALLBACK_STATIONS` — `KCRP`, `KMAF`, `KELP` — have never
    been fetched under this project's Synoptic token, and `C4-weather-ingestion.md` already
    documents that this token silently returns zero observation rows for some stations while
    metadata access still succeeds. A fallback that resolves to a station the token cannot
    read would pass the entire test suite and fail in production as an empty result, which is
    precisely the outcome WX-06 exists to prevent. Only a live pull can tell the difference.
  </why-human>

  <how-to-verify>
    Following this project's convention, Claude performs every automation step below and the
    human reviews the gathered evidence rather than running commands.

    1. Confirm a `SYNOPTIC_TOKEN` is available in the environment. If it is absent, stop and
       record the blocker rather than reporting a failed fallback — an absent token is a
       setup gap, not evidence about the station IDs.
    2. For each of the four cities, call the real, unmocked
       `weather_provider.fetch_weather([config.SYNOPTIC_FALLBACK_STATIONS[city]], start, end)`
       over a recent short window. Record, per city: the station ID, the row count, the first
       timestamp, and whether `air_temp`, `wind_speed`, and `wind_direction` are non-null.
       A zero-row result for any city is the finding this check exists to surface.
    3. Force one genuine end-to-end fallback with nothing mocked but the primary's failure:
       call `fetch_weather` with `provider="tceq"` against an invalid CAMS ID so
       `tceq_provider.fetch_tceq` raises against the real endpoint, and confirm the returned
       frame is non-empty, that `wind_source` and `temp_source` read `synoptic`, and that no
       `*_source` cell reads `tceq`. Capture the WARNING log line emitted.
    4. Repeat step 3 on the grid path with `provider="nsrdb"` and a real coordinate pair, with
       the NSRDB credentials deliberately unset — then confirm the observed behaviour is an
       `EnvironmentError`, NOT a fallback, and separately force a provider-side failure to
       confirm that path does fall back. This distinguishes the two branches against reality.
    5. Report every finding, including any city whose station returns zero rows, before
       requesting approval. If a station ID proves unreadable, propose a replacement ID rather
       than silently narrowing the fallback's coverage.
  </how-to-verify>

  <resume-signal>
    The human reviews the per-city live evidence and states "approved", or names the follow-up
    they want (for example, a replacement station ID for a city whose station returned zero
    rows). Execution does not continue on an unreadable station being silently accepted.
  </resume-signal>

  <acceptance-criteria>
    - A live row count and non-null field report exists for all four

    - One real station-path fallback and one real grid-path fallback were each observed
