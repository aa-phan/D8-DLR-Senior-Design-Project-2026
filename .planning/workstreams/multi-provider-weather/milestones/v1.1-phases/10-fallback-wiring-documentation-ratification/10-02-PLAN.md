Established by Plan 10-01 (read `10-01-SUMMARY.md` and the current `weather_provider.py` to
confirm before relying on any of it):

- `fetch_weather(location, start, end, provider="synoptic", *, fallback=True)` computes an
  eligibility flag before dispatching, and only wraps the dispatch in a `try` when that flag
  is true.
- `FALLBACK_PROVIDER`, `FALLBACK_ELIGIBLE_PRIMARIES`, `STATION_PATH_PROVIDERS`,
  `GRID_PATH_PROVIDERS`, `_fallback_city_for_request`, `_fallback_station_ids`, and
  `_attempt_fallback` all exist at module level.
- `config.SYNOPTIC_FALLBACK_STATIONS` maps the four `CITY_COORDINATES` keys to `KAUS`,
  `KCRP`, `KMAF`, `KELP`.

Pre-existing behaviour this plan must respect:

- `_fetch_grid` returns a frame that has already been through `attach_city(frame, lat=lat,
  lon=lon)`, and raises when the resolved `city` is null. Grid-path callers therefore rely on
  a `city` column being present.
- `_fetch_station(..., "synoptic")` returns a frame indexed by `(stid, datetime_utc)` UNLESS
  `_supplement_with_asos` actually supplied rows, in which case it is re-keyed to
  `(city, datetime_utc)` with `stid` demoted to a nullable column. Both shapes are possible
  outputs of a fallback.
- `attach_city` unconditionally assigns a `city` column. Assigning it to a frame that already
  carries `city` as an index level creates a name collision that breaks a later
  `reset_index()`, which `merge_observations._prepare_merge_side` performs.
- `units_def.PIPELINE_SCHEMA`'s four `*_source` keys are categorical with
  `allowed_values = KNOWN_PROVIDER_NAMES`, which already contains `"synoptic"`.
- `merge_observations(station_frame, grid_frame)` keys both sides on `(city, datetime_utc)`
  and uses `combine_first`, station side winning.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NSRDB API response to adapter | Untrusted third-party CSV/JSON crosses here; a failure arms the grid-path fallback |
| Synoptic API response to adapter, on a grid-shaped request | A station-shaped frame crosses into a grid-shaped contract |
| Adapter output to `merge_observations` and to C5/C7/C8 | A substituted provider's row crosses into a safety-relevant ampacity calculation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-07 | Spoofing | fallback frame's `solar_source` | critical | mitigate | Task 1 asserts an all-null Synoptic `solar_radiation` yields a null `solar_source` and no value of 1000; a verify pins that `fetch_timeseries` still does not fabricate solar |
| T-10-08 | Tampering | `_as_grid_shaped` city attribution | high | mitigate | The grid-path null-city guard already used by `_fetch_grid` is applied to the fallback frame too, so an unattributable row is never emitted |
| T-10-09 | Information disclosure | per-city fallback tests hitting the network | medium | mitigate | Every parametrized case monkeypatches `dlr_pipeline.fetch_timeseries`; the station-argument assertion doubles as proof no live call was made |
| T-10-10 | Repudiation | a merged row's field attributed to the asked-for rather than the actual provider | high | mitigate | Task 3 asserts `nsrdb` appears in no `*_source` cell of a fallback-sourced merged frame |
| T-10-11 | Denial of service | a per-city fallback loop amplifying requests against Synoptic's free tier | medium | accept | The fallback is one extra request per failed request with no retry; the four-city parametrization exists only in tests, which are fully mocked |
| T-10-12 | Elevation of privilege | fabricating a row when every provider is exhausted | critical | mitigate | Task 2 asserts both-failed and empty-fallback each raise, so a caller resolves toward its static rating per PROJECT.md's fail-safe commitment |
