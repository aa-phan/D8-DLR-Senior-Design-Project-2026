<objective>
Wire Synoptic as the automatic fallback behind `weather_provider.fetch_weather` for one
failure scenario, end to end: a TCEQ station-path request whose provider call fails returns a
usable Synoptic-sourced frame whose provenance honestly reads `"synoptic"`.

This is the phase's tracer. It touches every layer the phase will modify -- `config.py`'s
station table, `weather_provider.py`'s dispatch, the provenance layer, and the test suite --
on ONE path, so the fallback architecture is proven before it is generalised to the grid path
in Plan 10-02.

Purpose: WX-06 -- a primary provider failing must not leave a caller (C5/C7/C8) with a raise
or an empty frame when a working alternative source exists.
Output: a fallback-armed `fetch_weather`, a four-city Synoptic fallback station table, and a
test suite proving both that the fallback fires when it should and that it stays out of the
way when it must not.
</objective>

Facts established by Phases 6-9 that this plan builds on. Verify each against the source

- `weather_provider.fetch_weather(location, start, end, provider="synoptic")` type-dispatches
  `location` via `_validate_location_shape` into the literal strings `"station"` (non-empty
  `list[str]`) or `"grid"` (2-tuple of non-bool numbers), then calls `_fetch_station` or
  `_fetch_grid`. There is NO fallback logic anywhere in the module today.
- `_fetch_station` implements `provider="tceq"` (raises `ValueError` naming every supplied ID
  when `len(stids) != 1`, else delegates to `tceq_provider.fetch_tceq`) and
  `provider="synoptic"` (delegates to `dlr_pipeline.fetch_timeseries`, then
  `_supplement_with_asos`). Any other name hits a final `raise ValueError`.
- `_fetch_grid` implements `provider="open_meteo"` and `provider="nsrdb"`, each followed by
  `attach_city(frame, lat=lat, lon=lon)` and a raise when the resolved `city` is null. Any
  other name hits a final `raise ValueError` whose message contains `grid`, `open_meteo`, and
  `nsrdb`.
- `attach_provenance(frame, provider)` sets each of `wind_source`/`temp_source`/
  `humidity_source`/`solar_source` to `provider` ONLY on rows where a mapped source column is
  present AND non-null, and to `None` everywhere else. It raises `ValueError` for a provider
  not in `units_def.KNOWN_PROVIDER_NAMES`.
- `units_def.KNOWN_PROVIDER_NAMES` already contains `"synoptic"`. This phase needs NO schema
  change and NO `PIPELINE_SCHEMA_VERSION` bump.
- `resolve_station_city(lat, lon)` returns the nearest `config.CITY_COORDINATES` key, or
  `None` when either coordinate is absent, non-numeric, bool, or non-finite.
- `config.CITY_COORDINATES` keys are exactly `AUSTIN`, `CORPUS_CHRISTI`, `MIDLAND`, `EL_PASO`.
  `config.TCEQ_STATIONS` maps those keys to CAMS IDs `38`, `83`, `1095`, `41`.
  `config.ASOS_STATIONS` maps them to 3-letter FAA codes `AUS`, `CRP`, `MAF`, `ELP`.
- `dlr_pipeline.fetch_timeseries` does NOT fabricate solar. The hardcoded
  `obs["solar_radiation"].fillna(1000)` lives at `backend/dlr_pipeline.py:228` inside
  `run_pipeline`, a different function. A Synoptic frame from `fetch_timeseries` therefore
  carries an honest null where the station has no solar sensor.
- `backend/tests/weather_provider_test.py` uses module-level imports, plain asserts, no test
  classes, and `monkeypatch.setattr(<provider_module>, "<fetch_fn>", ...)` to avoid live
  network calls. Module-level `_START`/`_END` constants and `_synthetic_frame`,
  `_station_frame`, `_grid_frame`, `_tceq_frame`, `_nsrdb_frame` helpers already exist.
- `pytest.ini` sets `pythonpath = backend`, `testpaths = backend/tests`. Run pytest from the
  repository root.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TCEQ `daily_summary.pl` response to adapter | Untrusted third-party HTML crosses here; a failure on this boundary is what arms the fallback |
| Synoptic API response to adapter | Untrusted third-party JSON crosses here on the fallback path |
| Environment (`SYNOPTIC_TOKEN`) to adapter to log/exception | A credential crosses into text that may be logged or surfaced to a caller |
| Adapter output to downstream safety consumers (C5/C7/C8) | A provider substitution crosses here and must remain attributable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
