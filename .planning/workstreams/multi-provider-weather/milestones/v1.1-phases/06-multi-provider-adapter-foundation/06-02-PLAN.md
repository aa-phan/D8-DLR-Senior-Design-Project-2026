<objective>
Make `fetch_weather` accept both request shapes a multi-provider world needs — a station-ID list and
a `(lat, lon)` grid point — behind one parameter, and give the adapter the internal station→city
resolution that Plan 06-03's city-keyed merge depends on, without any caller learning that cities
exist.

Purpose: this is WX-05's headline. NSRDB and Open-Meteo (Phases 7-8) are lat/lon-based; TCEQ, ASOS
and Synoptic are station-based. `data_provider.md`'s closing section flagged this signature collision
as the design consequence to decide deliberately rather than discover mid-milestone. Landing it here,
with the currently-working Synoptic path untouched at every call site, is what lets Phases 7-10 add
providers instead of re-plumbing.

Output: a type-dispatched `location` parameter with an explicit shape guard; `lat`/`lon` captured out
of the Synoptic response that is already being fetched; a `resolve_station_city` helper that returns
a literal `CITY_COORDINATES` key or `None`, never a guess.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → `fetch_weather(location, ...)` | The `location` argument is the phase's new untrusted-shape surface: two structurally similar Python objects (a 2-element list and a 2-element tuple) select entirely different provider paths |
| Synoptic API response → `dlr_pipeline.fetch_timeseries` | `LATITUDE`/`LONGITUDE` are externally supplied and may be absent, null, or non-numeric for a given station or account tier (`06-RESEARCH.md` assumption A2) |
| `resolve_station_city` return value → `config.STATIC_RATINGS` / `config.CORRIDOR_ENDPOINTS` | A city key crossing here selects the static rating a corridor is compared against; a wrong key silently changes a safety-relevant number |
