<objective>
Make `provider="tceq"` a real, working choice on `weather_provider._fetch_station` by proving one
complete path end-to-end: `fetch_weather(["83"], start, end, provider="tceq")` fetches one calendar
day of Corpus Christi CAMS 83's `daily_summary.pl` report, parses its HTML table, converts units via
`units_def.Q`, converts local-standard-time hours to UTC with a fixed offset, range-checks the result,
and returns a provenance-tagged frame.

Purpose: TCEQ is the highest-integration-effort provider in the milestone — HTML report scraping, not
a JSON client. Proving one city, one day, through the *real* `fetch_weather` before building out
multi-day decomposition, four-city coverage and the fail-loud suite means an architectural
dead-end surfaces after one commit instead of after the whole module is written.

Output: a working `backend/tceq_provider.py`, its `config.TCEQ_STATIONS` lookup, the `"tceq"` dispatch
branch, and the `bs4` dependency pin that makes the scrape reproducible.

**Why CAMS 83 is the tracer's city:** it is the only one of the four chosen sites whose report carries
all four target parameters including Relative Humidity (09-RESEARCH.md CAMS Site Selection), so a
single happy path exercises every column the module can populate. The RH-absent sites (38, 1095) and
the MST offset (41) are Plan 09-02's expansion.

**Why the tracer is Task 3 rather than Task 1:** this plan's first `import bs4` is the first time any
provider module in this codebase imports it, and the package carries a `[SUS]` legitimacy verdict in
09-RESEARCH.md's audit. A blocking human legitimacy checkpoint and the dependency pin it approves must
land before the import does. Tasks 1 and 2 exist only to clear that gate and lay the config the tracer
reads; Task 3 is the vertical slice.

**Out of scope, deliberately:** no fallback or primary-selection logic (D-06 — that is WX-06/Phase 10).
This plan makes TCEQ a legal provider choice; it does not make it preferred over Synoptic anywhere.
</objective>
