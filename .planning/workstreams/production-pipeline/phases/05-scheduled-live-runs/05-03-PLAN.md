<objective>
Record every live run, and every city that failed or ran degraded, in Phase 4's `pipeline_run`
table (SCHED-01: "a failed city or provider in one run is recorded (row status or a run-log
table)"; OD-9: a city that fails outright writes no rating row and appears only in the run log).

Purpose: a crashed or timed-out city leaves no rating row, so only the run log can record it; Phase 6
uses this table to explain freshness breaches (E2E-02). A row inserted at the start and finished at
the end also shows a run that the job timeout killed.
Output: `backend/live_run_log.py`, runner wiring, tests; possibly a child opt-out in the orchestrator.
No schema change: Phase 4 created `pipeline_run` for this purpose.
</objective>
