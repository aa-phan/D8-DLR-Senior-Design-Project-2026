<objective>
Build the consumer-side checks, as consumers will see the system: a standard-library REST client,
an in-process fake of PostgREST for offline tests, and `e2e_verify_readonly.py` with read,
hidden-table and write-rejection checks (API-01 live half, E2E-03).

Purpose: OD-6 requires writes revoked explicitly, and 06-RESEARCH showed that an anon PATCH or DELETE
blocked only by RLS returns HTTP 200 with zero rows changed, so a status-only test can pass on a
misconfigured project. The write check demands the privilege-layer error AND an unchanged snapshot.
Per D-10 the tools read the URL and key from the environment and never print them. Per D-06 this is
offline build work; the owner runs the checks live in 06-09, 06-12 and 06-13.
Plain English for the owner:
- Read check: "a person with only the public key sees exactly one current rating per city, with the
  documented columns."
- Hidden check: "the private run log and the soak log cannot be read with the public key."
- Write check: "trying to add, change or delete data with the public key is refused, and the data
  afterwards is identical."
Output: client, verifier, fake server and tests. Nothing pushed.
</objective>
