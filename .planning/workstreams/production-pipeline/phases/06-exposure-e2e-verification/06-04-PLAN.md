<objective>
Build the E2E-02 instruments: a database-side freshness log that the owner schedules with pg_cron,
and a report that turns the soak window into a list of breaches with causes.

Purpose: E2E-02 needs evidence that, at any moment over at least 72 h, every city's latest valid_time
was within 90 min (OD-4), and every breach explained. 06-RESEARCH recommends a pg_cron log inside
Supabase (always on, no Actions minutes, not dependent on the owner's laptop) plus an exact measure
from the writes themselves, because a 5-minute probe only samples the sawtooth. Causes come from
Phase 5's run records, reusing its window check rather than re-deriving slot verdicts.
Output: one migration, three owner SQL files, a report tool with export and report subcommands, an
operator doc, offline and local-Postgres tests. Nothing is applied or scheduled here (06-06 does it).
</objective>
