<objective>
Build the database side of the 72 h soak: a consumer-invisible freshness log that reads the same
`is_stale` consumers see, the owner's pg_cron scripts to start and stop it, and the read-only probe
smoke check the owner runs before the 72 h clock starts.

Purpose: E2E-02 needs a record "at every probe" for at least 72 h. A pg_cron job inside Supabase is
always on, independent of GitHub Actions incidents and of the owner's laptop (06-RESEARCH), and D-14
makes it, not the alarm, the soak's record. Planner's choice under D-07: a short probe smoke check
(a few probes) runs before the clock, because a broken probe found at hour 40 would force a restart.
Plain English: "every five minutes the database writes down how old each city's current rating is,
using the same 90-minute rule the dashboard sees." Per D-06 nothing is applied or scheduled here;
06-09 applies the migration and 06-10 schedules the job.
Output: one migration, four owner SQL files and local-Postgres tests. Nothing pushed.
</objective>
