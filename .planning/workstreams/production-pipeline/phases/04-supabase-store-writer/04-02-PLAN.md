<objective>
Put the Postgres store on the production path (DB-02): `run_city_pipeline` takes a history
reader, the orchestrator reads and writes through a store, records each run in `pipeline_run`,
and `dlr_orchestrator --store postgres` selects it from the CLI. The CSV archive stays the default
for tests and backfill. Add the OD-3 forecast status and give the Postgres history the CSV archive's
row validation.

Purpose: ROADMAP SC2 ("a pipeline run pointed at Supabase reads history from Postgres and upserts
one row per city; re-running the same window changes no row count"), OD-3 (a failed ML forecast is
recorded per row), OD-9 (a city that fails outright writes no rating row; the failure goes to
`pipeline_run`). Phase 5's runner launches one orchestrator child per city with `--store postgres
--no-run-row` and writes the run row itself (05-03); its children read `summary[i]["archived"]`
as the row-written flag and `pipeline["forecast_status"]`.

Output: changes to `backend/city_pipeline.py`, `backend/dlr_orchestrator.py`,
`backend/supabase_store.py`, `backend/historical_archive.py`; new
`backend/tests/supabase_orchestrator_test.py`; additions to existing tests.
</objective>
