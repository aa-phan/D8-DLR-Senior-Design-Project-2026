<objective>
Land one real, production-quality end-to-end trained-model anomaly check: `AnomalyDetector.for_corridor("AUSTIN_CORPUS_CHRISTI")` loads a `scikit-learn` outlier estimator fitted offline on genuinely real Open-Meteo Archive historical weather for that corridor's two endpoint cities, and `check(raw_data, rating)` returns a real `(bool, str)` verdict in which that model's judgement of the raw `wind`/`temp`/`solar` reading is OR-combined with whichever existing heuristic branch also ran.

Purpose: ANOM-01's whole claim is that a *fitted model object* — not a rolling mean-and-standard-deviation threshold and not a forecast-residual comparison — contributes a decision, behind an unchanged `check(raw_data, rating) -> (bool, str)` call shape that `DLRSafetyMonitor`'s G6 site and its fail-safe wiring never learn about. Proving that whole path in one commit (config, real data, fit, persisted artifact, lazy load, live verdict, unchanged fail-safe resolution) catches an architectural dead end now, before the measurement machinery and the validation record are built on top of it.

Output: a new `ANOMALY_ML_*` config block, `backend/anomaly_training.py` (offline assembly, fit, atomic persistence, CLI), the additive model branch inside `backend/anomaly_detector.py`, and the invariant tests that keep the fail-safe contract and the OR-combination rule honest.

**Feature-set resolution (Claude's Discretion in CONTEXT.md, resolved here on evidence).** The model is fitted on exactly three features — `air_temp`, `wind_speed`, `solar_radiation` — with NO time-of-day or seasonal encoding, despite `ampacity_forecast.build_ml_features`' `hour_sin`/`hour_cos` precedent. Reason: `DLRSafetyMonitor._gate_sensor` shows `raw_data` carries only `sensor_status`, `link_status`, `wind`, `temp`, `solar` — there is no timestamp at the `check()` call site. A feature the inference path cannot compute would make every live check raise and latch G6 in permanent fallback, and adding a timestamp to `raw_data` is Track 1's pipeline scope, out of bounds by the same reasoning D-02 applies to ERCOT load. The multivariate value ANOM-01 asks for survives without it: a jointly implausible three-variable combination is detectable in the three-dimensional envelope alone.

**Granularity resolution (Claude's Discretion in CONTEXT.md, resolved here on evidence).** One model per corridor, fitted on the *pooled* hourly readings of both endpoint cities (RESEARCH.md Pattern 3, Assumption A1) rather than one model per city. Reason: `raw_data` carries no location field, so a per-city artifact selector would have nothing to key on at the call site. `for_corridor` stays the selection mechanism, exactly as it already is for `k`.
</objective>
