<objective>
Turn the tracer's single fitted estimator into a measured, evidence-selected one: fit all three D-03 candidates across a contamination grid on each corridor's real pooled readings, measure each one's false-positive rate on a strictly-later clean holdout and its recall on two labelled categories of synthetically injected corruption, measure the existing rolling mean-and-standard-deviation baseline on the identical rows, select each corridor's winner by a single stated deterministic rule, persist it, and write every number to one machine-readable report.

Purpose: ANOM-02 requires the model's false-positive/false-negative behavior to be validated against real historical data and compared against the existing baseline — and 02-RESEARCH.md's central finding is that this is an *unlabeled* problem, unlike Phase 1's regression target. Real historical weather contains no labelled sensor faults, so the clean half of the bar is directly measurable but the recall half only exists if corruption is deliberately injected into otherwise-real rows. Building both halves here, with the baseline scored on the same rows, is what makes Plan 02-04's record a transcription of measurement rather than an assertion.

Output: the measurement and bake-off machinery inside `backend/anomaly_training.py`, its config tunables, both corridors' winners persisted, and `data/models/anomaly_validation_report.json`.

**Winner-selection rule (stated here, before any measurement exists).** Among the candidate-and-contamination pairs whose measured false-positive rate on the clean holdout is at or below `config.ANOMALY_ML_MAX_FALSE_POSITIVE_RATE`, select the pair with the highest pooled recall across both injection categories; break a tie by the lower false-positive rate, then by `CANDIDATE_ESTIMATORS` insertion order. When NO pair meets the false-positive ceiling, select the pair with the lowest measured false-positive rate and mark the report entry as not meeting the ceiling — the phase still ships the additive branch per D-05/D-06 (an OR-combined branch only ever adds caution), and Plan 02-04 states the shortfall plainly per D-07. Selection raises only on a genuinely missing or non-finite measurement, mirroring `forecast_training.select_winner`'s refusal to pick a winner on a missing number.
</objective>

**2. `backend/anomaly_training.py` — the measurement functions**, each with a docstring in this module's established register naming the decision or success criterion it serves:
- `chronological_split(frame, holdout_fraction=None)` — sorts by `datetime_utc`, splits at `int(len(frame) * (1 - holdout_fraction))`, returns the earlier slice and the later slice with indexes reset. Defaults `holdout_fraction` from config. Raises `ValueError` naming the row count when either side would be empty or when the fit side would hold fewer rows than `anomaly_detector.ROLLING_BASELINE_MIN_ROWS`, since the baseline arm cannot be constructed below that floor.
- `_out_of_range_value(column)` — returns a value outside that column's `DLRSafetyMonitor` bound by a fixed, documented margin (e.g. the upper bound plus 30 for wind, plus 35 for temperature, plus 600 for irradiance), so the injected value is unambiguously beyond the physical gate rather than marginal.
- `_implausible_combination(fit_frame)` — returns the three-value triple for the in-range category, derived from the fit slice's own distribution: the high quantile of `solar_radiation`, the low quantile of `air_temp`, and the low quantile of `wind_speed`, each computed from the fit slice and each therefore a value the real data actually contains. Document explicitly that this is what makes the category test G6's unique multivariate contribution rather than re-testing G3: every component individually passes the range gate and individually occurs in the record; only the simultaneous combination does not.
- `inject_anomalies(frame, category, rng=None, rate=None)` — copies the frame (never mutates the input), selects `round(len(frame) * rate)` row positions with a seeded generator defaulting to `config.ANOMALY_ML_RANDOM_SEED`, and applies the named category's corruption to those positions. Returns the corrupted copy and the boolean injection mask. Raises `ValueError` naming the valid categories for an unknown one.
- `_dlr_amps_for(frame, corridor)` — converts a frame's three raw columns into a `dlr_amps` series using `corridor_discretization.corridor_geometry(corridor)`'s `ConductorConfig` and `thermal_model.ieee738_ampacity`, with an explicit float cast on the result (the function returns an array even for scalar input). This is the one conversion both the baseline's history and the baseline's scored rows go through, so both sides of the comparison sit on the same physics.
- `score_model(model, frame)` — builds the feature matrix through the existing `build_feature_matrix` and returns a boolean array true where the estimator's prediction entry point returns the outlier label. One call on the whole matrix, never a per-row loop.
- `score_rolling_baseline(corridor, fit_frame, frame)` — constructs `AnomalyDetector.for_corridor(corridor, history=<fit slice with its derived dlr_amps column>, load_model=False)`, then loops the scored frame's rows, converting each row's raw readings through `_dlr_amps_for` and calling the detector's `check({}, rating)`. Returns the boolean verdicts. Passing an empty `raw_data` is correct and deliberate here: this arm is the existing derived-rating heuristic, which reads only `rating`, and `load_model=False` guarantees the model branch cannot contaminate the baseline's numbers.
- `validate_candidate(corridor, fit_frame, holdout_frame, name, factory, contamination)` — fits a fresh estimator on the fit slice's feature matrix (capping the row count at `config.ANOMALY_ML_SVM_MAX_TRAIN_ROWS` for the kernel candidate only, taking the earliest rows so time order is preserved), then computes: the false-positive rate as the fraction of clean holdout rows the model flags; the same fraction for the rolling baseline; per-category recall as the fraction of injected rows flagged, for both detectors, computed only over the mask positions; and the pooled recall across both categories. Returns a mapping carrying every one of those rates plus `contamination`, the fit and holdout row counts, the injected count per category, and the capped training row count actually used.
