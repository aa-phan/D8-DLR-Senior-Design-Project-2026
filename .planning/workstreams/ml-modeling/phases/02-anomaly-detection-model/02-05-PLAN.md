Purpose: Plan 02-02 wrote a must-have into its own frontmatter promising that this report makes "a shortened run visible in the evidence rather than hidden behind a score," and the phase's threat register entry T-02-09 names exactly that visibility as its Repudiation mitigation. 02-VERIFICATION.md reproduced the opposite live: `--bakeoff --years 1` followed by `--bakeoff --years 1 --corridor MIDLAND_EL_PASO` left the report holding only `MIDLAND_EL_PASO`, with `AUSTIN_CORPUS_CHRISTI`'s entire measurement history — every candidate-and-contamination number the losing arms included (D-03), the measured winner and its selected contamination (D-04) — erased with no warning. `docs/data-science/decisions/anomaly_detection_model.md` is a direct transcription of that JSON, so a well-intentioned single-corridor retrain performed between record updates would corrupt the source-of-truth evidence ANOM-02's published record depends on, and the honesty standard D-07 binds this workstream to would be resting on a file that can silently lose its own history.

The fix is not merely "do not delete." It is the stronger thing the must-have literally asks for: the report must make the shortened run **visible**. So each corridor entry carries the provenance of the invocation that produced it, and every merge run prints which corridors it refreshed, which it carried forward from an earlier run, and which it pruned as no longer belonging to `config.CORRIDOR_ENDPOINTS`.
