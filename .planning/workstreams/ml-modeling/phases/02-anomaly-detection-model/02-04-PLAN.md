<objective>
Write the ANOM-02 validation record from the real measurement runs, and correct the C10 spec that still says this component does not exist.

Purpose: ANOM-02 is not discharged by a model that works — it is discharged by a written record of the model's measured false-positive and false-negative behavior against real historical data, compared against the existing baseline, that states whether the model met expectations. D-07 makes the standard explicit: report the numbers honestly whichever way they come out, exactly as Phase 1's `forecasting_model.md` recorded NOT MET for both corridors rather than dressing up an intra-candidate win. Phase 1 also established that a "the model didn't win" phase still passes verification, because the engineering and the honesty are the deliverable, not a guaranteed accuracy result.

Output: `docs/data-science/decisions/anomaly_detection_model.md` (new, tracked) and a corrected `docs/data-science/specs/C10-anomaly-detection.md`.

**This plan changes no code.** Every number comes from `data/models/anomaly_validation_report.json` and `data/models/anomaly_load_characterization.json` as produced by Plans 02-02 and 02-03. If a number needed for the record is absent from those reports, re-run the generating command rather than computing it by hand — a figure that exists only in the document is a figure nobody can reproduce.
</objective>
