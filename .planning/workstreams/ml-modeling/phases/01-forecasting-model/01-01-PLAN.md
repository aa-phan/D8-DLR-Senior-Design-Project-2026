<objective>
Land one real, production-quality end-to-end ML ampacity forecast: `ampacity_forecast.forecast_ampacity(history, method="ml")` returns a `ForecastResult` whose point forecast comes from a fitted `scikit-learn` estimator trained on genuinely real historical data (Open-Meteo Archive backfill run through IEEE 738), selected per corridor from the frame's own `corridor` column, with the confidence band still produced by the existing `backtest_residuals` walk-forward machinery.

Purpose: FCST-01's whole claim is that a *fitted model object* — not a last-value read and not an EWM average — produces the number, behind an unchanged public signature. Proving that path end-to-end in one commit (dependency -> real data -> fit -> persisted artifact -> runtime inference -> the same four `PIPELINE_SCHEMA` columns) catches an architectural dead end now rather than after the bake-off and the validation record are already built on top of it.

Output: a pinned `scikit-learn` dependency, `backend/forecast_training.py` (offline assembly + fit + atomic persistence), the `"ml"` method inside `backend/ampacity_forecast.py`, new `config.py` tunables, and the invariant tests that keep the model honest.

**Assumption-delta decision: no-change.** `FORECAST_METHODS` is already a multi-value tuple holding `"naive"` and `"ewm"` — it was never a singular assumption, so adding a third method value extends an already-generalized identity rather than promoting a primary case. No refactor of the enum's shape is warranted.
</objective>

**4. `backend/ampacity_forecast.py` — the `"ml"` method.** Extend `FORECAST_METHODS` to `("naive", "ewm", "ml")`. Then add, in this module (NOT in the training script — the runtime owns the feature contract and training imports it, so exactly one implementation exists):
- `ML_FEATURE_COLUMNS: tuple[str, ...]` — the single ordered feature-name tuple the estimator is fitted on and predicted from: one `dlr_amps_lag_<h>h` name per offset in `config.FORECAST_ML_LAG_HOURS`, then `dlr_amps_roll_mean_<w>h`, then each name in `config.FORECAST_ML_FEATURE_WEATHER_COLUMNS`, then `hour_sin` and `hour_cos`.
- `build_ml_features(frame: pd.DataFrame) -> pd.DataFrame` — public. Takes a `DatetimeIndex`-ed frame carrying `dlr_amps` plus the weather columns; returns a frame with exactly `ML_FEATURE_COLUMNS`, in that order, indexed identically. Lags via `.shift(h)` on `dlr_amps`; the rolling mean via `.rolling(window, min_periods=window).mean()` shifted by 1 so the current row's own value is excluded; `hour_sin`/`hour_cos` from `index.hour` as `sin/cos(2*pi*hour/24)`. Rows whose features are not fully determined (the leading `max(lags)` rows) come back with nulls — the caller drops them; this function never invents a value for a missing input.
- `_extract_ml_frame(history: pd.DataFrame) -> pd.DataFrame` — private. Requires `dlr_amps`, `corridor`, `datetime_utc` and every column in `config.FORECAST_ML_FEATURE_WEATHER_COLUMNS`; raises `ValueError` naming the missing column(s) otherwise. Parses `datetime_utc` into a `DatetimeIndex` (raises `ValueError` if unparseable — the `"ml"` path needs real timestamps for lag ordering and hour-of-day, and silently falling back to a positional index the way `_extract_series` does would misorder the lags), sorts ascending, and drops rows with a null `dlr_amps`. The `"ml"` branch of `forecast_ampacity` derives its series as this frame's `dlr_amps` column rather than calling `_extract_series`, so the series and the feature frame are structurally the same rows and positional slicing in `backtest_residuals` cannot drift apart.
- `_corridor_of(frame: pd.DataFrame) -> str` — private. Returns the frame's single `corridor` value; raises `ValueError` naming the distinct values found when the frame carries more than one (`historical_archive.read_history(corridor=...)` already filters, so a mixed frame is a caller bug, not a case to average over), and raises when the value is absent from `config.CORRIDOR_ENDPOINTS` (this is also the path-traversal guard for step 5 — the corridor key is validated against a closed set before it is ever formatted into a filename).
- `_model_path_for(corridor: str) -> str` — private. `os.path.join(config.FORECAST_ML_MODEL_DIR, config.FORECAST_ML_MODEL_FILENAME_TEMPLATE.format(corridor=corridor))`. No caller-supplied path parameter exists anywhere on the ML path.
- `_MODEL_CACHE: dict` and `_load_corridor_model(corridor: str)` — private. Imports `joblib` lazily *inside the function body* so importing this module stays free of file I/O, network calls and any `sklearn`/`joblib` import, preserving the module's existing no-side-effects-on-import contract and keeping naive/EWM usable where `scikit-learn` is absent. Caches per corridor. When the artifact file does not exist, raise `FileNotFoundError` naming the corridor, the expected path, and the training command that produces it — never degrade to another method (see this plan's first prohibition).
- `_point_forecast(series, method, halflife_min=None, history=None, model=None)` — append two optional keyword parameters; `"naive"`/`"ewm"` ignore both and their code paths are untouched. The `"ml"` branch raises `ValueError` when `history` is `None`, builds features from `history` via `build_ml_features`, takes the LAST fully-determined feature row, raises `ValueError` naming the offending column if any value in that row is null (a missing weather reading on the inference row is a failed forecast, not a zero), and returns `float(model.predict(row_as_2d)[0])`. `model` is always supplied by the caller — this module never invokes an estimator's training entry point, only its prediction entry point.

The existing loop, residual definition and strict-prefix exclusivity are unchanged. For `"ml"`: load the fitted model ONCE before the loop and pass it plus `history.iloc[:i]` into each `_point_forecast` call, so the FIXED already-fitted model is walked forward and nothing is refitted per step. This remains the only source of band width in the module.

**5. `backend/forecast_training.py` — new offline module**, a standalone entry point not imported by the runtime pipeline (mirroring `ercot_data_retriever.py`'s `__main__`-driven convention). It imports `ampacity_forecast` for `build_ml_features`, so the dependency points training -> runtime and never the reverse. Public surface:
- `fetch_city_weather(city: str, years: int) -> pd.DataFrame` — resolves `config.CITY_COORDINATES[city]`, then calls `open_meteo_provider.fetch_open_meteo` ONCE PER CALENDAR YEAR over the `years` complete calendar years ending with the most recent complete one, concatenating the results. Per-year chunking lives here, in the caller, because `fetch_open_meteo`'s documented contract is one HTTP request per call; this also sidesteps RESEARCH Assumption A5's unverified single-request range cap.
- `corridor_training_frame(corridor: str, years: int) -> pd.DataFrame` — the phase's real-data spine. For each of the corridor's two endpoint cities (`config.CORRIDOR_ENDPOINTS`): fetch its weather, compute `perpendicular_wind` against the corridor's bearing (obtain the bearing and the per-corridor `ConductorConfig` from `corridor_discretization.corridor_geometry(corridor)` — do not recompute either), then `ieee738_ampacity`. Inner-join the two cities on `datetime_utc`. Reduce to one corridor-level series with the codebase's established weakest-link `min()` convention: the corridor's `dlr_amps` at each timestamp is the elementwise minimum of the two cities' ampacities, and that row's weather is the *winning* (lower-ampacity) city's own observation — the same "the archived weather is always the weather that produced the archived rating" rule `corridor_discretization` already follows. Wrap every ampacity read in `float(...)` (RESEARCH Pitfall 2 — `ieee738_ampacity` returns an ndarray even for scalar input). Return a frame with exactly `historical_archive.ARCHIVE_COLUMNS`, with `static_rating` from `corridor_geometry`, `status="ok"`, `fallback=False`, `bottleneck_index` as the index (0 or 1) of the winning endpoint city, and `schema_version=historical_archive.ARCHIVE_SCHEMA_VERSION`. Before returning, validate every row through `units_def.validate_pipeline_row(historical_archive._validation_row(row), strict=False)`, drop the failures, and emit ONE warning line naming the dropped count and the first offending message — mirroring `read_history`'s own validate-before-training behavior (mitigates T-01-01).
- `build_training_matrix(frame: pd.DataFrame) -> tuple[pd.DataFrame, pd.Series]` — index the frame by `datetime_utc`, call `ampacity_forecast.build_ml_features`, and build the target as `dlr_amps` shifted FORWARD by exactly `config.FORECAST_HORIZON_MINUTES` worth of rows (1 row at the hourly cadence). Drop every row where any feature or the target is null. Return `(X, y)` with `X.columns` equal to `ampacity_forecast.ML_FEATURE_COLUMNS` in order, and with `X`/`y` carrying the feature timestamp and target timestamp respectively so the relationship is inspectable by a test rather than only asserted in prose.
- `fit_corridor_model(X, y)` — fits `sklearn.ensemble.HistGradientBoostingRegressor` with a fixed `random_state` and returns the fitted estimator. (This plan fits one candidate so the path is proven; Plan 02 turns this into D-01's evidence-based two-candidate bake-off.)
- `persist_corridor_model(model, corridor) -> str` — `os.makedirs(config.FORECAST_ML_MODEL_DIR, exist_ok=True)`, `joblib.dump` to a temp file in that same directory, then `os.replace` onto `ampacity_forecast._model_path_for(corridor)`. The temp-then-replace is the concurrency/interruption guarantee: a run killed mid-write, or two runs racing on one corridor, can never leave a torn `.joblib` for the runtime loader (see this plan's Flagged Assumptions). Returns the final path.
- `main(argv=None)` — `argparse` with `--corridor` (default: every key in `config.CORRIDOR_ENDPOINTS`) and `--years` (default `config.FORECAST_ML_TRAINING_YEARS`). Per corridor: assemble, write the assembled frame to `os.path.join(config.FORECAST_ML_MODEL_DIR, config.FORECAST_ML_TRAINING_FRAME_TEMPLATE.format(corridor=corridor))` so the exact real frame that trained the model can be replayed through `forecast_ampacity`, build the matrix, fit, persist, and print the row count, date span and persisted path. Guarded by `if __name__ == "__main__": main()`.
