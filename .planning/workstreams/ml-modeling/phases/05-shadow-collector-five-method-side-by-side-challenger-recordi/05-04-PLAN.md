<objective>
Give `reference_ml_refit_24h` a real persisted artifact and a real live prediction path, closing
the one candidate 05-02 could only honestly stub as unavailable.

Purpose: 05-RESEARCH.md's own finding is that no persisted `reference_ml_refit_24h` artifact exists
anywhere in this repo (`data/shadow/models/` holds only `ml_wind_corrected_*.joblib` and
`ml_cooling_corrected_*.joblib`). That is the SHALLOWER of two gaps. The deeper one, found by
direct read of `ampacity_forecast.build_ml_features` (not stated in 05-RESEARCH.md): arm 5's
feature set needs lagged `dlr_amps` at 1, 2, 3, and 6 hours before the prediction anchor plus a
6-hour rolling mean (`config.FORECAST_ML_LAG_HOURS`, `config.FORECAST_ML_ROLLING_WINDOW_HOURS`) --
not just the single point value `persistence_24h` needs. The shadow collector's own JSONL log
cannot supply this: it logs twice daily, twelve hours apart, with no hourly granularity at all. So
even with a persisted artifact, there is nothing in this collector's own history arm 5 could read
its lag features from -- building the live feature row requires a genuinely new live data path,
not just a loader.

The resolution mirrors `persistence_24h`'s own decision-time discipline (D-05), generalized: at
decision time, fetch a short window of near-real-time station observations (TCEQ primary, Synoptic
fallback -- the SAME `weather_provider.fetch_weather` the anchor fetch already uses, just a window
query instead of a single latest-row query) for both endpoint cities, covering the seven hourly
points `anchor_time - 6h` through `anchor_time`. Run each city's own hourly observation through the
SAME physics (`thermal_model.perpendicular_wind` + `ieee738_ampacity`) and the SAME weakest-link
reduction (`forecast_training.corridor_weakest_link`) training used to build arm 5's own truth
series (`forecast_experiment._arm5_truth_frame`), producing a short corridor-level truth-proxy
series shaped exactly like that function's own output. Feed that series through
`ampacity_forecast.build_ml_features` (reused, unedited -- the SAME function
`forecast_training.build_training_matrix` already calls) and take its last row (the one whose
index is `anchor_time`) as the single live feature vector. If any of the seven hours is missing or
null for either city, there is no honest feature row to build -- report `unavailable` naming the
gap, never interpolate.

This also means `reference_ml_refit_24h` is architecturally corridor-level-native with no per-city
decomposition at inference time, exactly as it is at training time (the model never sees per-city
values, only the weakest-link-reduced series) -- its log entry carries `per_city_ampacity_amps:
null` with an explicit `per_city_not_applicable_reason`, a deliberate, documented exception to
D-06's per-city-preservation language, not an omission.

Output: a one-time offline fit+commit script producing real persisted artifacts for both corridors,
the live truth-proxy reconstruction, and `ReferenceRefit24hShadowMethod`'s real predict path.
</objective>
