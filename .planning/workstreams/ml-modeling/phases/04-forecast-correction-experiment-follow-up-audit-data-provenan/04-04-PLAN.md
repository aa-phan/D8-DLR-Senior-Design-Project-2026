<objective>
Ask the question Phase 3 never asked: not "how close was the forecast," but "how often would it have
told an operator the line could carry more than it actually could, by how much, and for how long."

Purpose: mean absolute error is symmetric and a dynamic line rating decision is not. An
under-prediction leaves capacity unused; an over-prediction tells an operator a conductor can carry
current it cannot. Phase 3's entire comparison is built on MAE and RMSE, both of which charge the same
price for both. Its own Open Questions section names the gap — "this record scores mean absolute error
alone; it says nothing about calibrated confidence bounds around a corrected forecast" — and defers it.
This plan closes it, and adds the comparison that makes the closure useful: at a matched acceptable
overrating rate, how much usable capacity does each candidate actually retain against persistence and
against the static rating? That is the number an operator would care about, and no candidate has ever
been scored on it.

Two disciplines make the answer honest rather than impressive. The first is the three-period split: a
quantile model is fitted on one period, its calibration offset learned on a second, and its calibration
checked on a third, all chronologically disjoint and asserted so — because a quantile that is
calibrated and checked on the same rows is calibrated by construction and tells you nothing. The
second is a limitation that has to travel with every number in this section, not sit in a footnote: the
"truth" being compared against is itself an IEEE 738 output computed from reanalysis weather. Every
overrating rate here measures a model's self-consistency against a simulation. It is not evidence about
a real conductor, and this section must not be readable as if it were.

Output: an overrating profiler measuring frequency, magnitude and run length; a regime breakdown whose
low-wind boundary is the conductor's own measured convection crossover rather than a round number; a
fit/calibrate/evaluate quantile pipeline scored with scikit-learn's own pinball loss; a matched-rate
retained-capacity table as the headline comparison; and a published section in which the
reanalysis-scope limitation appears beside every number it qualifies.

**Why the low-wind boundary is measured rather than chosen.** D-03 asks for a low-wind regime because
IEEE 738's convective term is most sensitive there; D-04 asks separately that low-wind sensitivity be
distinguished from numerical instability. Both are better served by a boundary derived from the physics
than by a round number: the wind speed at which natural convection overtakes forced convection for this
corridor's own conductor is a computable quantity, and binning around it means the low-wind bin is the
regime where the floor is actually active rather than an arbitrary slice.

**Why run length carries its own caveat.** The scored rows are the exact-lead subset, four per day, six
hours apart. Three consecutive scored overratings therefore span twelve hours of clock time with two
unscored six-hour gaps inside them. Calling that a "twelve-hour exceedance" would assert something
about hours nobody measured. The report says what it measured — consecutive scored rows — and says what
it does not know.
</objective>

**1. `overrating_profile(truth, prediction, timestamps, *, cadence_hours=None)`.**

Overrating is a prediction above the truth: the model told a consumer the line could carry more than
the modelled safe rating. Compute the count and the rate over all scored rows; then, over the
overrating rows only, the mean, median, 95th-percentile and maximum exceedance in amperes. Then the run
lengths: group consecutive overrating rows in timestamp order and return the distribution of run
lengths with their counts, plus the longest run and its start and end timestamps.

Carry the cadence honestly. Record the scored cadence in hours, the wall-clock span a run of k rows
covers, and an explicit statement in the returned value — not only in the docstring — that a run
counts consecutive *scored* rows and says nothing about the unscored hours between them. The
downstream record quotes this statement; it must be data, not prose the writer has to remember.

Return nulls rather than not-a-number values for the magnitude statistics when there are no overrating
rows, so a zero-overrating candidate serializes cleanly and a reader cannot mistake a null for a
computed zero.

**2. `convection_crossover_wind_speed(corridor, *, air_temp_c=None)`.**

The convective term is the elementwise maximum of a forced and a natural expression. Find the
perpendicular wind speed at which the two are equal for this corridor's own conductor configuration, at
a stated ambient temperature, by evaluating the thermal module's existing public natural-convection
function and its convective-heat-loss function over a wind grid and locating the crossing — or by a
bisection on the difference, whichever you can justify as more precise. Do not reimplement either
expression; call them.

Return the crossover wind speed, the ambient temperature it was computed at, the conductor
configuration's identifying parameters, and a note that the crossover moves with ambient temperature.
Then assert the result: evaluate the thermal module's convective function slightly below and slightly
above the crossover and confirm that below it the value equals the natural-convection term and above it
does not. A crossover that does not satisfy that is not the crossover.

**3. `overrating_by_regime(scored_frame, prediction, *, corridor, minimum_bin_rows=None)`.**

Project the valid-time truth wind onto the corridor bearing through the thermal module's own
projection function — the convective term consumes perpendicular wind, and binning on raw wind speed
would mix a strong cross-corridor wind with a weak along-corridor one. Bin the perpendicular wind with
the measured crossover as the lowest interior boundary, so the bottom bin is the regime where the
natural-convection floor is actually active, plus a small number of bins above it spanning the observed
range. Report the bin edges and state which edge is the measured crossover and which are chosen
spans — a reader must be able to tell the physically-derived boundary from the presentational ones.

Compute the full overrating profile per bin. Add secondary breakdowns by ambient temperature band and
by hour of day, each with per-bin row counts. Flag any bin whose row count is below a stated minimum
rather than reporting a rate from it; a 100% overrating rate over three rows is not a finding.

Assert that the bins partition the scored rows: the per-bin row counts sum to the total. A silent gap
or overlap in the bin edges would distribute rows into neither bin or both, and the reported rates
would not describe the data.

| Calibration period → calibration check | A quantile calibrated and checked on the same rows is calibrated by construction and its coverage number is self-fulfilling. |
| Target overrating rate → achieved overrating rate | A derating fitted on one period does not necessarily hit its target on the next. Reporting the target as though it were the result overstates how tightly a method can be operated. |
| Frozen test rows → any period in this plan | All three sub-periods lie inside the ABLATION basis and pass the frozen-window guard. |
| Chosen bin edge → physically derived bin edge | A round-number low-wind boundary would make the low-wind finding an artifact of presentation rather than of the convective term's actual sensitivity. |
| Hand-rolled asymmetric loss → pinball loss | Pinball loss at the median equals half the mean absolute error; a hand-rolled version that misses the factor reports every loss wrongly. |
