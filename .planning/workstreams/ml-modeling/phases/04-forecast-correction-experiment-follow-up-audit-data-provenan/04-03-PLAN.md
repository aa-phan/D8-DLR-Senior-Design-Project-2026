<objective>
Replace "beats persistence" with a comparison that can survive a statistician, and do it on real rows
that Phase 3's frozen test set never touches.

Purpose: the frozen record's verdict rests on six candidates scored once against one baseline, with
confidence intervals from an i.i.d. bootstrap over an hourly series that is not i.i.d. Three separate
weaknesses live in that sentence, and D-02 names all three. First, hourly ampacity residuals are
temporally dependent, so resampling individual rows understates the interval — the honest interval is
wider than the one on the page, and nobody has measured by how much. Second, beating persistence does
not establish superiority over `raw_forecast`, `ml_wind_corrected`, or `reference_ml_refit_24h`; those
comparisons were never made, and at Midland the winning candidate's advantage over the refit model is
0.66 amps on MAE while the refit model is better on RMSE. Third, a winner chosen by largest point
margin from six candidates scored once is a discovery, not a confirmation.

None of that can be recomputed from Phase 3's own outputs: 04-RESEARCH.md established that the harness
persisted aggregate scores only — no per-row predictions, no residuals, no fitted models. So this plan
recomputes from assembled data on the ABLATION basis Plan 04-01 measured, and makes one deliberate
change from Phase 3's setup that turns a limitation into a strength: the fitted arms are refit on the
train rows alone and scored on the validation rows, which makes the measurement genuinely
out-of-sample for exactly the three candidates the audit most needs to re-examine. Phase 3's own
validation-split numbers could not do that, because its fitted arms were fit on train plus validation.

That buys a real independent replication on a different held-out period — which is stronger evidence
about the candidates' ordering than a recomputation of the frozen interval would have been. What it
does not buy is a confirmation: that calendar range was read during Phase 3's development, and the
only basis that can carry a confirmation claim is the fresh post-frozen-window period, whose row count
Plan 04-01 measured and which this plan reports at whatever size it actually is.

Output: a paired block bootstrap validated to reduce to the i.i.d. case at block length one, a
block-length sensitivity sweep with a stability verdict, every pairwise margin between the four real
fitted/raw candidates at both corridors, MAE and RMSE side by side with every ordering disagreement
flagged, per-row residuals persisted so nobody has to re-run this, and a Strengthened-comparison
section that states which basis each number rests on.

**Why block length one is the correctness gate.** A hand-rolled block bootstrap is easy to get
subtly wrong — an off-by-one in the block start range, a concatenation that exceeds n and is truncated
unevenly, a resample count that differs from the comparison. At block length one, a moving block
bootstrap is *definitionally* an i.i.d. bootstrap. So the implementation must reproduce an
independently-computed i.i.d. percentile interval at that block length, within resampling noise. If it
does not, the block machinery is broken and every wider interval it produces is wider for the wrong
reason.

**Why the width comparison is method-matched.** The harness's existing interval uses the bias-corrected
accelerated method; a block bootstrap cannot use it, because the acceleration term is not well defined
for block resampling. Comparing a block percentile interval against an i.i.d. accelerated interval
would change two things at once and attribute the whole difference to block resampling. So this plan
computes an i.i.d. *percentile* interval on the same difference series as the matched comparator, and
reports the harness's accelerated interval separately as the frozen record's own method.
</objective>

**1. `paired_block_bootstrap_margin(errors_arm, errors_baseline, *, block_length, method="moving", n_resamples=None, confidence_level=None, random_state=None)`.**

Mirror the harness's i.i.d. bootstrap exactly in contract and discipline: take raw residuals and
absolute them internally so no caller has to remember to; raise on a shape mismatch naming both shapes;
define the point margin as the mean of the baseline's absolute errors minus the mean of the arm's;
short-circuit a zero-variance difference series to a point-mass interval at the point value with a
comment stating the same reason the i.i.d. version gives; default the resample count, confidence level
and seed to the harness's three existing constants.

Where it differs, differ deliberately and document it in the docstring. Resample contiguous blocks of
`block_length` consecutive elements of the difference series, with replacement, concatenating enough
blocks to reach the original length and truncating the last one, and take the resampled mean; repeat
for the resample count. Support both a moving variant (block starts drawn from the range that keeps a
whole block inside the series) and a circular variant (block starts drawn from the whole series with
wraparound), selected by `method`, and record which was used in the return value. Build the interval by
the percentile method at the requested confidence level, and state in the docstring why the
bias-corrected accelerated method the i.i.d. version uses is not available here: its acceleration term
is estimated from a jackknife over independent observations, which block resampling does not provide.
Raise a `ValueError` naming the block length and the series length if the block length is not a
positive integer no larger than the series length.

Draw every random number from a single generator seeded with the resolved seed, so two calls with the
same arguments return byte-identical bounds.

**2. `iid_percentile_margin(errors_arm, errors_baseline, *, n_resamples=None, confidence_level=None, random_state=None)`.**
