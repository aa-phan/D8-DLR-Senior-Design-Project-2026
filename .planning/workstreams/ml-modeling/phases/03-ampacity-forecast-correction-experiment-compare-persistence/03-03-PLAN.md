<objective>
Lift the experiment from Plan 03-01's single-city slice to the corridor level for both corridors, and add the
two arms that need no machine learning: the NWP-wind-delta baseline and the oracle diagnostic.

Purpose: two of D-02's seven approaches are pure arithmetic over the anchored pair frame, and the corridor
reduction is a single shared helper away now that Plan 03-02 has extracted it. Landing all three here — before
any correction model exists — means the harness is complete and fair on its non-ML arms, so when the ML arms
arrive in Plan 03-05 the only new thing being tested is the model, not the plumbing around it. It also gets the
oracle's structural separation in place early, where it is cheap, rather than retrofitting it once a ranking
function already exists and already has the oracle in its input.

Output: corridor-level assembly for both corridors, arm 1, arm 6, the arm registry that structurally excludes
the oracle, and the tests that keep all of it honest.

**Why the oracle's separation is structural rather than a label.** The oracle substitutes the wind that was
actually observed at the valid time — information no forecaster could have had. Its only legitimate use is to
bound how much benefit a perfect wind correction could possibly capture. If it sits in the same mapping as the
real arms, some future reader, some future sort, or some future summary line will treat it as the winner, and
the phase will have published a number that cannot be achieved. RESEARCH.md's anti-pattern list says this
plainly: make it a structural property, not a caption. So it gets a different key in the report object, it
never enters the candidates mapping, and a test asserts the exclusion by inspecting the ranking function's
actual input rather than by checking a string.

**Why arm 1 is worth having at all.** It is the cheapest possible use of a forecast: keep every observed input
at its last-known value and move only the wind, by exactly the amount the forecast says the wind will move.
It costs nothing beyond the anchored frame that already exists, and it separates two very different questions
— whether the forecast carries useful wind information, and whether pushing a whole forecast weather vector
through the physics helps. If arm 1 beats arm 2, the forecast's non-wind variables are actively hurting.
</objective>

| Assembled frame → per-arm prediction | An arm that reads a valid-time observation becomes an oracle without announcing it |
| Scored report → human reader | A number presented as a winner will be read as deployable |
