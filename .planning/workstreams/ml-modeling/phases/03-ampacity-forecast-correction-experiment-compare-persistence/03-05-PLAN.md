<objective>
Commit the bar before measuring against it, then wire the three remaining arms and prove the comparison is
fair: identical test timestamps for all seven, no arm reading post-issue-time information, no contact with the
leakage-carrying production artifact, and every difference reported with an interval rather than as a bare
point estimate.

Purpose: this is the plan where the experiment becomes capable of producing a result, so it is also the plan
where every way of producing a dishonest result has to be closed. Three of those ways are live here. Arm 5
could silently load a model trained on the test range. Any arm could quietly read a valid-time observation.
And with a test slice on the order of 875 rows per corridor, a winner declared on a two-ampere MAE gap would
be noise dressed as a finding. Each gets a structural defence rather than a caution.

Output: the decision record's pre-committed sections, arms 3/4/5 wired, the leakage suite, and paired
bootstrap intervals throughout.

**Why the Expectation is a separate task committed first.** ROADMAP SC5 requires the Expectation section to be
committed before the test-set run, and `forecasting_model.md` models exactly what that looks like: a bar
chosen for a stated reason, written above the results, and then honoured even when the answer is unwelcome —
that record says "NOT MET" twice rather than reframing an intra-candidate win as an overall pass. The ordering
is enforceable here because tasks within a plan are ordered and each commits separately, so git history shows
the bar predating the machinery that could measure against it.

**The bar, and why it has two clauses.** An arm beats persistence only if its held-out MAE is lower on BOTH
corridors AND the paired bootstrap 95 percent interval on the difference excludes zero. The first clause is
inherited directly from `forecasting_model.md`'s reasoning: no project document contains an independently
sourced accuracy target, so inventing an amperage threshold would be a fabricated baseline, and beating the
method the arm is meant to replace is the most defensible non-fabricated bar available. The second clause is
new to this phase and is forced by its data: the exact-one-hour-lead filter yields four rows per day per city,
so the test tail is roughly an order of magnitude smaller than the 21,910 rows Phase 1 scored. Without an
interval, this phase would be less able to distinguish a real improvement than the phase it was created to
follow up.

**Why arm 5 is the reference and not the champion.** D-02 includes the current production method refit on
train-plus-validation so the comparison is against a fairly-trained version of what actually ships, not
against an artifact that saw the test range during its own training. `forecasting_model.md` records that the
persisted winner on both corridors is the neural-network candidate, so that is the architecture refit here.
Loading the persisted artifact instead would be leakage, and would additionally populate the runtime module's
never-invalidated per-corridor cache for the remainder of the process.
</objective>
