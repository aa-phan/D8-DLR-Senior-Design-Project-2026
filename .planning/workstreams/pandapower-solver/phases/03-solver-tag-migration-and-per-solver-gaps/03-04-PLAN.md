<objective>
Make the pandapower engine's runs carry their tag end to end (DB-02, D-04, D-05): the solver package registers `pandapower` with prefix `pp` when it is imported, the engine stamps `solver` and `solver_version` on its study results (Phase 2's hand-off: `psse_version=None`, the pandapower version as `solver_version`), and the closing rehearsal writes a tagged four-city pandapower study through the real writer into a throwaway database.

Purpose: the pandapower half of success criterion 2, the "only the closing tagged-write rehearsal with the pandapower engine needs Phase 2" part of the roadmap. It also proves the Python vocabulary equals the migration's, so the job never builds a run the database refuses.
Output: two small production edits (`api.py`, `engine.py`), the two existing pandapower tests that the cross-check of plan 03-02 now requires to pass the tag, and `backend/tests/pandapower_solver_tag_test.py`.
</objective>
