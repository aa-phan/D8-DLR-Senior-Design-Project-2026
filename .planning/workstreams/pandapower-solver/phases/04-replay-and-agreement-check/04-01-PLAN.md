<objective>
Build the only route by which recorded PSS/E runs reach the replay (D-01): a read-only SQL export that the owner of the Supabase project runs in the SQL editor, and an ingest step that validates the exported file and writes a private snapshot under `data/private/`. Nothing here connects to a database; the replay of later plans reads only the snapshot.

Purpose: D-01 keeps credentials and connection code out of the compute path, so "the replay writes nothing" (AGR-01) holds by construction. This plan also gives the owner's first look at the corpus as counts only: how many runs, how many distinct mapping and case hashes, and how many match the local mapping and the session's recorded case hash (the owner's default for the first export).
Output: `backend/pandapower_job/recorded.py`, `supabase/ops/export_psse_runs_for_replay.sql`, the shared test helper and three test files (two run here, one needs Postgres).

D-01 supersedes the research's route 1 (a read-only session with a statement guard through the writer credential). The tests that route needed (a recording fake connection, a guard wrapper) are not built; their purpose is served by "no module of this phase imports a driver" (pinned here and again in plan 04-03), the export file being one SELECT, and the database-tier proofs.
</objective>
