<objective>
Build the pure comparison of one recorded PSS/E run against one replayed run, and the gate that turns many comparisons into a pass, fail or incomplete word (AGR-02, AGR-03; decisions D-02 and D-04). No solver, no snapshot, no file: the module takes plain row dictionaries, so every rule can be proven on hand-built rows with a tolerance edge on both sides.

Purpose: the check is only worth anything if "pass" cannot be reached by comparing nothing, by quantisation noise passing for agreement, or by a widened tolerance, and if "fail" is reachable. This plan puts those rules in one small module that the replay (plan 04-03) and the report (plan 04-04) both use.
Output: `backend/pandapower_job/agree.py` and `backend/tests/pandapower_agree_test.py`.
</objective>

- The stored tables hold only violations. A key present on one side only therefore says that side's element exceeded its limit by `exceeded_by`, and that the other solver's value is on the other side of the limit.
