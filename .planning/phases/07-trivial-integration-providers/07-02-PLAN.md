**`backend/open_meteo_provider.py`** — new module. Docstring states that importing it has no side
effects, that it requires no API key or token, and that the Archive API variant was chosen for
historical-backfill depth with the base URL isolated in one constant so the Historical Forecast
variant remains a one-constant change. Imports: `logging`, `requests`, `pandas as pd`, `units_def`.
Module-level `log = logging.getLogger(__name__)`.

Define these module constants:
  - `OPEN_METEO_ARCHIVE_BASE = "https://archive-api.open-meteo.com/v1/archive"` — a fixed constant,
    never built from caller input.
  - `HOURLY_TO_PIPELINE: dict[str, str]` mapping the provider's hourly variable names to
    `PIPELINE_SCHEMA` column names: `temperature_2m` to `air_temp`, `wind_speed_10m` to `wind_speed`,
    `wind_direction_10m` to `wind_direction`, `shortwave_radiation` to `solar_radiation`,
    `relative_humidity_2m` to `relative_humidity`.
  - `OPEN_METEO_HOURLY_VARS: tuple[str, ...] = tuple(HOURLY_TO_PIPELINE)` — derive the requested
    variable list from the mapping rather than writing it a second time, so the request and the
    response parsing cannot drift apart.
  - `EXPECTED_HOURLY_UNITS: dict[str, str]` giving the unit string the response should echo for each
    provider variable, matching `PIPELINE_SCHEMA`'s units for the mapped column.

Define `_to_archive_date(value: str) -> str`: coerce with `pd.Timestamp(value)`, localize to UTC when
tz-naive and convert to UTC when tz-aware, then `strftime("%Y-%m-%d")`. Raise `ValueError` naming the
offending value when it cannot be parsed. The Archive API takes calendar dates, while callers in this
codebase pass both full ISO timestamps and bare dates.

Define `fetch_open_meteo(lat: float, lon: float, start: str, end: str) -> pd.DataFrame`. Issue
exactly one `requests.get(OPEN_METEO_ARCHIVE_BASE, params=..., timeout=60)`. Params: `latitude`,
`longitude`, `start_date` and `end_date` through `_to_archive_date`, `hourly` as a comma-joined
`OPEN_METEO_HOURLY_VARS`, `wind_speed_unit` set to the metres-per-second value, and `timezone` set to
UTC. Do not fall back to the endpoint's default wind-speed unit and do not add a per-variable or
per-day loop — one request, full variable set, which is the requirement itself.

Call `raise_for_status()`, then parse the body with `r.json()` inside a `try` that re-raises as
`ValueError` naming that the body was not JSON. Then validate the body shape before building the
frame: `hourly` must be a dict and must carry a non-empty `time` list; each key of
`HOURLY_TO_PIPELINE` must be present in `hourly` and its array length must equal `len(time)`. Raise
`ValueError` naming the specific missing or mismatched key otherwise — never pad, never truncate,
never insert a column of nulls in place of a variable the provider did not return.

Build the frame with `datetime_utc` from `pd.to_datetime(hourly["time"], utc=True)` — the `utc=True`
is load-bearing, because the provider's ISO strings carry no offset suffix even when the request asks
for UTC, and a tz-naive column aligns against nothing downstream. Then one column per
`HOURLY_TO_PIPELINE` entry, in mapping order.

Add `_range_check(frame) -> None` mirroring `asos_provider._range_check`: for each of the five mapped
columns read the low/high bounds from `units_def.PIPELINE_SCHEMA[column]["range"]` and raise
`ValueError` naming the column, the offending value and both bounds when any non-null value falls
outside. Call it last, before returning. Additionally, when the response carries an `hourly_units`
object, compare each present entry against `EXPECTED_HOURLY_UNITS` and raise `ValueError` naming the
variable, the echoed unit and the expected one on a mismatch — the response states which unit it
actually used, which makes this the cheapest possible detector for a request parameter that was
dropped or ignored upstream.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Open-Meteo Archive API response → `PIPELINE_SCHEMA` columns | An unauthenticated third-party JSON body becomes the training data C9/C10 learn from. Wrong units or fabricated nulls propagate into a model rather than into a single reading. |
| Caller coordinates → `attach_city` → per-city static rating selection | The city resolved from the caller's coordinates decides which corridor's static rating a downstream consumer applies. A null or wrong city mis-selects it. |
| Grid path ↔ station path dispatch | D-04 requires the grid path be reachable only with `provider="open_meteo"`; a dispatch leak would serve model reanalysis data to C5/C7/C8 as if it were a station observation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

No padding, truncation or null-column substitution at any step. Pinned by the five `test_fetch_open_meteo_raises_when_*` body-shape tests. |
| T-07-08 | Tampering | Wind-speed unit | high | mitigate | The request sets the metres-per-second wind unit explicitly rather than accepting the endpoint default, the response's `hourly_units` echo is compared against `EXPECTED_HOURLY_UNITS`, and `_range_check` re-reads `PIPELINE_SCHEMA` bounds. A wind value left in the endpoint's default unit is otherwise an ordinary in-range-looking number below roughly 50. Pinned by `test_fetch_open_meteo_requests_metres_per_second_wind`, `test_fetch_open_meteo_raises_when_the_echoed_wind_unit_is_wrong`, `test_fetch_open_meteo_raises_when_a_value_is_out_of_schema_range`. |
| T-07-09 | Tampering | Timezone handling | high | mitigate | The provider returns offset-free ISO strings even for a UTC request, so `pd.to_datetime(..., utc=True)` is mandatory.
