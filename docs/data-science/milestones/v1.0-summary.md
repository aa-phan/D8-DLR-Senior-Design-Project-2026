# v1.0 MVP — Shipped 2026-09-10

**4 phases, 7 GSD-tracked plans, 19 tasks.** (Phases 1–2 were the pre-GSD implementation,
recorded as complete to reflect reality rather than re-planned from scratch; Phases 3–4 were
fully GSD-tracked.)

## What shipped

- **Safety monitor unified with the real thermal model.** `DLRSafetyMonitor` now calls
  `thermal_model.ieee738_ampacity` directly instead of a placeholder linear formula, made
  per-location constructible, and all five fail-safe gates (G1–G5) resolve toward the static
  rating instead of a stale or optimistic guess.
- **Corridor spatial discretization.** The two D-01 corridors (Austin↔Corpus Christi,
  Midland↔El Paso) are each discretized into 5 geodesic points; per-point weather resolves
  through a broadened, credential-free station-proximity search; the corridor-level rating is the
  minimum across points, with the bottleneck point identified. Any point that exhausts every
  candidate station resolves to the corridor's static rating instead of raising — no data-loss
  gap in the corridor path.
- **Learned anomaly detection (gate G6).** One anomalous reading now travels
  archive → naive forecast → per-location anomaly detector → gate G6 → the static rating, through
  the same `_fallback` helper Phase 3 shipped — fail-safe under a raising detector, an unwritable
  disk, or a poisoned row.
- **True out-of-sample forecasting.** The forecaster's confidence band is a real expanding-window
  walk-forward backtest, not an in-sample residual band; an EWM method was added behind the same
  signature; forecast output publishes through `PIPELINE_SCHEMA` v2's five additive columns.
- **DS-F5 closed.** `process_dlr_to_hourly`, `run_pipeline`, and `plot_dlr_summary` now resolve
  `config.STATIC_RATINGS.get(city, config.DEFAULT_STATIC_RATING)` instead of unconditionally
  reading the 900 A default — the last open v1.0 requirement, caught and closed by a
  purpose-built Phase 5 after a milestone audit found it.
